# CLI 参考

在 `` 下运行 CLI。仓库启动脚本会构建 CLI distribution，
并转发全部参数：

```bash
./wasmline-cli/cli.sh <command> [options]
```

## 命令

| 命令 | 结果 |
|---|---|
| `build` | 编译选中的 AOT profile、签名一个 manifest，并创建离线 ZIP |
| `compile` | 编译选中的 AOT profile，并写入 `aot-build-record.json` |
| `manifest` | 为已有 build record 签名 |
| `generate-key-pair` | 生成 manifest 格式接受的 Ed25519 密钥对 |
| `aot-profiles list` | 列出 catalog profile 及其 ID |
| `aot-profiles describe <id>` | 显示一个 profile 的描述和构建宿主 |
| `componentize` | 创建或检查作为 AOT 输入的 raw Component |
| `tools download` | 下载锁定的 Component 工具 |
| `wit generate` | 生成 WIT binding |
| `component validate` | 校验 Component |
| `component inspect` | 输出 Component 的 WIT |

CLI 不接受已删除的 `download` 命令、`--wasmtime` 目录或任意 compiler
executable。AOT compiler 必须来自摘要锁定的 catalog。已删除的
`--aot-compatibility`、`--aot-version-range` 与 `--min-sdk` 也没有别名；AOT 覆盖
范围只能通过 `--aot-generations` 选择。

## 构建 Package

```bash
./wasmline-cli/cli.sh generate-key-pair --save

./wasmline-cli/cli.sh build \
  --input plugin.wasm \
  --aot-generations latest \
  --target pulley64 \
  --target x86_64-linux \
  --auto-download \
  --plugin-id com.example.plugin \
  --version 1.0.0 \
  --build-timestamp 0 \
  --key build/wasmline/keys/ed25519_private.key
```

`--aot-generations` 可以重复传入。每个取值只能是稳定的 `x.y.z` Wasmline 版本、
精确的小写 `latest`，或形如 `FROM..THROUGH` 的闭区间，且 `FROM` 必须是稳定版本，
`THROUGH` 可以是稳定版本或 `latest`。取值都是精确 token：CLI 不会拆分逗号列表、
不裁剪空白、不接受开放式区间，也不接受多于一个 `..` 分隔符。`latest` 指 CLI 内置
catalog 的 Wasmline 版本，而不是远程最新发行版。省略该 option 会选择本地 catalog
中保留的全部 generation；重复取值会并入同一个并集：

```bash
./wasmline-cli/cli.sh compile \
  --input plugin.wasm \
  --aot-generations 1.0.0 \
  --target pulley64

./wasmline-cli/cli.sh compile \
  --input plugin.wasm \
  --aot-generations 1.0.0 \
  --aot-generations 1.0.1..latest \
  --target x86_64-linux
```

区间两端都必须位于 catalog 的
`minimumSupportedWasmlineVersion`..`currentWasmlineVersion` 范围内。对当前保留的
catalog，`--aot-generations 1.0.0..latest` 因此与省略该 option 选出同样的 generation。
空 token、倒置区间、以 `latest..1.0.1` 这类符号值作为起点，或越界的 endpoint 都会
被拒绝，不会被裁剪为相交部分。解析到同一 generation 的不同取值以及复用的 backend profile
都会去重并确定性排序。CLI 会在任何工具下载、Component 准备、编译或签名之前，
一次性解析 catalog 边界与 profile，因此选择错误会在写出 package 之前暴露。这些
输入是用于选择 catalog generation 的 Wasmline 版本，CLI 仍不接受任意 Wasmtime
版本或 profile ID。

## Raw Export ABI

对于 `CORE_WASM + RAW_EXPORT`，使用与 Gradle `RawAbiMetadata` 相同的 JSON 格式：

```json
{
  "version": 1,
  "exports": [
    {
      "name": "add_i32",
      "kind": "FUNCTION",
      "signature": {
        "parameters": ["I32", "I32"],
        "results": ["I32"]
      }
    }
  ],
  "imports": [],
  "memoryExport": "memory",
  "requiredFeatures": []
}
```

```bash
./wasmline-cli/cli.sh build \
  --input plugin.wasm \
  --execution-model CORE_WASM \
  --invocation-protocol RAW_EXPORT \
  --export-name add_i32 \
  --raw-abi-metadata raw-abi.json \
  --target pulley64 \
  --key build/wasmline/keys/ed25519_private.key
```

plugin-core codec 会拒绝未知字段和无效类型，并在创建 build record 前对 export、
import 与 feature 列表排序。`contractMetadata` 只用于其他注记，不能替代 raw ABI。

## 输出结构

```text
build/wasmline/
├── output/com.example.plugin-1.0.0/
│   ├── manifest.wlm
│   ├── artifacts/sha256/
│   │   ├── 4f/4f13c7...a920.cwasm
│   │   ├── 91/91aa42...c810.wasm
│   │   └── b8/b8072d...0f31.pwasm
│   └── debug/
│       ├── manifest.json
│       ├── aot-build-record.json
│       └── artifact-index.json
├── dist/com.example.plugin-1.0.0.zip
└── keys/
    ├── ed25519_private.key
    └── ed25519_public.key
```

一个签名 manifest 描述全部选中的 profile。Core package 的 Web `.wasm` 在 Native
profile 列表之外只保存一份。Component raw Wasm 仅是构建输入，相同字节共用一个
内容寻址文件。

离线 ZIP 包含全部产物。远程 Loader 校验 manifest，选择一个 variant，只下载该文件，
不会下载 ZIP。

编译和签名使用 staging 目录。编译、签名或 ZIP 替换失败时，上一次 package 目录和
ZIP 保持不变。

只有 Gradle 提供 `wasmlineCheckAotCompatibility`，用于比较本地 catalog 与最新稳定
发行版。CLI 编译保持离线，只读取随 CLI 打包的 catalog。
