# CLI 参考

在 `` 下运行 CLI。仓库启动脚本会构建 CLI distribution，
并转发全部参数：

```bash
./wasmline-cli/cli.sh <command> [options]
```

## 命令

| 命令 | 结果 |
|---|---|
| `build` | 编译选中的 AOT profile、签名一个 manifest，并创建离线 ZIP |
| `compile` | 编译选中的 AOT profile，并写入 `aot-build-record.json` |
| `manifest` | 为已有 build record 签名 |
| `generate-key-pair` | 生成 manifest 格式接受的 Ed25519 密钥对 |
| `aot-profiles list` | 列出 catalog profile 及其 ID |
| `aot-profiles describe <id>` | 显示一个 profile 的描述和构建宿主 |
| `componentize` | 创建或检查作为 AOT 输入的 raw Component |
| `tools download` | 下载锁定的 Component 工具 |
| `wit export` | 输出规范的 `wasmline:service` WIT，供非 Kotlin guest 使用 |
| `wit generate` | 用锁定的 `wit-bindgen` 生成 guest binding（`--lang`） |
| `component validate` | 校验 Component |
| `component inspect` | 输出 Component 的 WIT |

CLI 不接受已删除的 `download` 命令、`--wasmtime` 目录或任意 compiler
executable。AOT compiler 必须来自摘要锁定的 catalog。已删除的
`--aot-compatibility`、`--aot-version-range` 与 `--min-sdk` 也没有别名；AOT 覆盖
范围只能通过 `--aot-generations` 选择。

## 导出 Service WIT

```bash
./wasmline-cli/cli.sh wit export --output build/wasmline/wit
```

该命令写出 `build/wasmline/wit/wasmline.wit`，内容为当前 CLI 版本携带的规范
`wasmline:service@1.0.0` contract。`--output` 指定目录，默认值是
`build/wasmline/wit`；不存在的目录会创建，已有 `wasmline.wit` 会覆盖。命令同时输出
该文件的 `WIT SHA-256`；把同一文件作为 `--wit` 传入构建时，记录的
`component.wit.sha256` 就是这个值，算法见
[组件服务协议](/zh/docs/component-service)。

`wit export` 只复制资源，不生成 binding，也不下载 Component 工具。将导出的目录
交给 guest 语言的 binding generator，例如 `wit-bindgen c`、`wit-bindgen cpp`
或 Rust 的 `wit_bindgen::generate!`。

`wit generate` 使用与 Gradle 相同的锁定 `wit-bindgen`：

```bash
./wasmline-cli/cli.sh wit generate --wit build/wasmline/wit --lang c --world plugin
```

`--lang` 只接受 `kotlin`、`rust`、`c`、`cpp`、`go`、`csharp`、`moonbit`、
`markdown` 之一，默认 `kotlin`。取值区分大小写，未知值在选项解析阶段失败。
`--kotlin-imports` 只对 `kotlin` 有效，其默认值为 `impl.*`。输出目录默认是
`build/generated/wasmline/wit`；生成前会删除该语言后缀的文件，生成后若没有产出
任何该类文件则命令失败。`--lang csharp` 会自动补上必需的
`--runtime native-aot`。

## 构建 Package

```bash
./wasmline-cli/cli.sh generate-key-pair --save

./wasmline-cli/cli.sh build \
  --input plugin.wasm \
  --aot-generations current \
  --target pulley64 \
  --target x86_64-linux \
  --auto-download \
  --plugin-id com.example.plugin \
  --version 1.0.0 \
  --build-timestamp 0 \
  --key build/wasmline/keys/ed25519_private.key
```

`--aot-generations` 可以重复传入；省略该 option 时选择 `current`。每个取值只能是
以下之一：

- 具体的稳定 `x.y.z` 版本；
- 具体的 `MIN..MAX` 闭区间；
- 精确的小写策略 token：`current`、`latest`、`earliest` 或 `all`；
- 形如 `current:before=N`、`current:after=N`（两种字段顺序均可的
  `current:before=N:after=M`）、`latest:before=N` 或 `earliest:after=N` 的窗口。

`current` 选择包含 CLI 内置 catalog 的 Wasmline 版本所在的 generation。
`latest` 与 `earliest` 分别选择本地保留的最新与最早 generation；`all` 显式选择
本地全部 generation，代价可能很高。窗口计数是额外的相邻数量：锚点 generation
始终包含在内，所以 `current:before=1:after=1` 覆盖三个 AOT generation。计数必须
是非负十进制整数；负数、溢出、带前导零的计数、重复或未知字段、`latest:after=N`
这类不受支持的锚点方向、`..latest` 这类符号 endpoint、逗号列表、首尾空白以及多个
`..` 分隔符都会被拒绝。token 不做归一化；重复传入的选择会并入同一个并集：

```bash
./wasmline-cli/cli.sh compile \
  --input plugin.wasm \
  --aot-generations 1.0.0 \
  --target pulley64

./wasmline-cli/cli.sh compile \
  --input plugin.wasm \
  --aot-generations 1.0.0..1.0.1 \
  --aot-generations latest:before=1 \
  --target x86_64-linux
```

每个具体 endpoint 都必须位于 catalog 的
`minimumSupportedWasmlineVersion`..`currentWasmlineVersion` 范围内，窗口请求的相邻
generation 也必须在本地存在。倒置区间、越界或本地不可用的选择，以及其他非法 token
都会被拒绝，不会被裁剪为相交部分。解析到同一 generation 的不同取值以及
复用的 backend profile 都会去重并确定性排序。选择完全基于随 CLI 打包的本地 catalog
解析，不访问网络。CLI 会在任何工具下载、Component 准备、编译或签名之前，一次性解析
catalog 边界与 profile，因此选择错误会在写出 package 之前暴露。这些输入是用于选择
catalog generation 的 Wasmline 版本；CLI 仍不接受任意 Wasmtime 版本、profile ID，
也不接受已删除的 `--aot-compatibility`、`--aot-version-range` 与 `--min-sdk`。

## Raw Export ABI

对于 `CORE_WASM + RAW_EXPORT`，使用与 Gradle `RawAbiMetadata` 相同的 JSON 格式：

```json
{
  "version": 1,
  "exports": [
    {
      "name": "add_i32",
      "kind": "FUNCTION",
      "signature": {
        "parameters": ["I32", "I32"],
        "results": ["I32"]
      }
    }
  ],
  "imports": [],
  "memoryExport": "memory",
  "requiredFeatures": []
}
```

```bash
./wasmline-cli/cli.sh build \
  --input plugin.wasm \
  --execution-model CORE_WASM \
  --invocation-protocol RAW_EXPORT \
  --export-name add_i32 \
  --raw-abi-metadata raw-abi.json \
  --target pulley64 \
  --key build/wasmline/keys/ed25519_private.key
```

plugin-core codec 会拒绝未知字段和无效类型，并在创建 build record 前对 export、
import 与 feature 列表排序。`contractMetadata` 只用于其他注记，不能替代 raw ABI。

## 输出结构

```text
build/wasmline/
├── output/com.example.plugin-1.0.0/
│   ├── manifest.wlm
│   ├── artifacts/sha256/
│   │   ├── 4f/4f13c7...a920.cwasm
│   │   ├── 91/91aa42...c810.wasm
│   │   └── b8/b8072d...0f31.pwasm
│   └── debug/
│       ├── manifest.json
│       ├── aot-build-record.json
│       └── artifact-index.json
├── dist/com.example.plugin-1.0.0.zip
└── keys/
    ├── ed25519_private.key
    └── ed25519_public.key
```

一个签名 manifest 描述全部选中的 profile。Core package 的 Web `.wasm` 在 Native
profile 列表之外只保存一份。Component raw Wasm 仅是构建输入，相同字节共用一个
内容寻址文件。

离线 ZIP 包含全部产物。远程 Loader 校验 manifest，选择一个 variant，只下载该文件，
不会下载 ZIP。

编译和签名使用 staging 目录。编译、签名或 ZIP 替换失败时，上一次 package 目录和
ZIP 保持不变。

只有 Gradle 提供 `wasmlineCheckAotCompatibility`，用于比较本地 catalog 与最新稳定
发行版。CLI 编译保持离线，只读取随 CLI 打包的 catalog。
