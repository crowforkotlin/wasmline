# Gradle Plugin

The `crow.wasmline` plugin registers build tasks for Kotlin Multiplatform
modules that declare a `wasmWasi` target. It uses the same AOT catalog,
compiler resolver, signing code, and package writer as the CLI.

## Signing and Host Trust

`manifest.privateKeyFile` is the package owner's Ed25519 private key. It is
read only by the assembly task to sign `manifest.wlm`; it is never generated
into a Host application. Keep it in a CI secret or an untracked file.

The Host has the opposite responsibility: configure the public keys it trusts
through `trust`. The plugin generates
`crow.wasmline.generated.WasmlineHostTrust` in `commonMain` for a Kotlin
Multiplatform project, or in `main` for a Kotlin JVM project. The generated
object implements `WasmlineTrustedKeys`, so application code does not contain a
public-key hex value or construct a key set.

```kotlin
wasmline {
    manifest {
        privateKeyFile = file("keys/package-2026.private")
        publicKeyId = "package-2026"
    }
    trust {
        publicKey(
            algorithm = "Ed25519",
            keyId = "package-2026",
            publicKeyHex = "5a778289bee0c57b05a1c48c8ef312da6ce8e4e4f13fc1a2e8e5aa4cde7ae0db",
        )
        // A UTF-8 file containing the same hexadecimal public key also works.
        // publicKeyFile(file("keys/package-2026.public"), keyId = "package-2026")
    }
}
```

Use the generated object for signed package loads:

```kotlin
import crow.wasmline.generated.WasmlineHostTrust
import crow.wasmline.loader.WasmlineLoadOptions

val options = WasmlineLoadOptions(trustedKeys = WasmlineHostTrust)
```

The Loader's `WasmlineLoadOptions` remains explicit so an application can use
different trust sets for different loads. Set `trust.sourceSet`,
`trust.kotlinPackage`, `trust.objectName`, or `trust.generatedSourcesDirectory`
when the defaults do not match the Host project. Declare several `publicKey` or
`publicKeyFile` entries with distinct `keyId` values to rotate keys. When a
`keyId` is used, the package owner must set the same value through
`manifest.publicKeyId` so the Loader can select that key. An unlabelled Host key
remains a compatibility fallback; for one unlabelled key, leave both values
unset.

Configure the private signing key only through `manifest.privateKeyFile`. The
plugin intentionally does not accept a private-key string in the DSL: it would
be easy to expose through source control, a build scan, or Gradle state.
Public-key Hex is non-sensitive and is supported directly.

## AOT Profile Selection

Native AOT builds compile the local catalog generations configured through
`aotCompatibility`. Omitting the block, leaving it empty, or configuring only
`suppressCompatibilityWarning` selects the generation containing the currently
introduced Wasmline build-tool version; the first `generations` call replaces
that implicit current default, and later calls add their strategies to a union.
The selection is independent of the artifact target: `targets` controls which
files are written, while the configured generations decide which AOT profiles
are compiled.

```kotlin
import crow.wasmline.gradle.WasmtimeTarget
import crow.wasmline.plugin.core.aot.AotGenerations

wasmline {
    manifest {
        pluginId = "com.example.plugin"
        version = "1.0.0"
        buildTimestamp = 0L
        privateKeyFile = file("keys/ed25519_private.key")
    }
    wasmtime {
        aotCompatibility {
            generations(AotGenerations.Current)
        }
        targets = listOf(
            WasmtimeTarget.PULLEY_64,
            WasmtimeTarget.X86_64_LINUX,
        )
        autoDownload.set(true)
    }
}
```

Named strategies select one generation, a typed window, or concrete versions:

```kotlin
import crow.wasmline.plugin.core.aot.AotGenerations

wasmline {
    wasmtime {
        aotCompatibility {
            generations(AotGenerations.Current(before = 1))
            generations(AotGenerations.Latest)
            generations(AotGenerations.Earliest(after = 1))
            generations(AotGenerations.All)
            generations("1.0.0")
            generations(AotGenerations.Versions(min = "1.0.0", max = "1.0.1"))
            generations(versions = listOf("1.0.0", "1.0.1"))
            generations(min = "1.0.0", max = "1.0.1")
            suppressCompatibilityWarning.set(false)
        }
    }
}
```

| Call | Selects |
|---|---|
| `generations(AotGenerations.Current)` | The generation containing the currently introduced build-tool version |
| `generations(AotGenerations.Current(before = 1, after = 1))` | The anchor generation plus one earlier and one later AOT generation, which must exist locally |
| `generations(AotGenerations.Latest)` / `Latest(before = 1)` | The newest local generation, optionally with earlier neighbors |
| `generations(AotGenerations.Earliest(after = 1))` | The oldest local generation plus one later neighbor |
| `generations(AotGenerations.All)` | Every generation retained in the local catalog |
| `generations("1.0.0")` | The generation containing that concrete stable Wasmline version |
| `generations(AotGenerations.Versions(...))` | The same point, collection, or closed-interval selection typed directly |
| `generations(versions = listOf(...))` | The generations containing those concrete versions; at least one required |
| `generations(min = "1.0.0", max = "1.0.1")` | Every generation intersecting the closed concrete interval |
| Omitted `aotCompatibility` | The current generation |

An omitted, empty, or warning-only block selects the current generation. `All`
is opt-in and may compile every locally retained generation, which can be
expensive. `Current`, `Latest`, and `Earliest` are anchored on the packaged
catalog: `Latest` is the newest locally retained generation, and `Current`
resolves through the packaged build-tool release version, so the two coincide
while no newer generation is retained. Future generations are not remotely
discoverable, so `Current(after = 1)` fails when the local catalog has no
successor. Window counts are additional neighbors — the anchor generation is
always included — and they count AOT generations, not Maven release versions or
backend profile changes. A requested neighbor that does not exist locally fails
instead of being clipped.

Once an explicit call replaced the default, later calls contribute to a union
instead of being appended to the current default. Strings passed to the
version overloads are always concrete `x.y.z` versions; there is no symbolic
version string, no `from`/`through` overload, and no vararg form that could
silently read two versions as an interval. Every concrete version must lie
inside the catalog's supported
`minimumSupportedWasmlineVersion`..`currentWasmlineVersion` bounds; an inverted,
out-of-range, or otherwise invalid selection is rejected instead of being
clipped to the intersecting part. Generations, requested backends, and reused
backend profiles are deduplicated and sorted deterministically, so several
versions from one generation compile once. These inputs are Wasmline versions
that select catalog generations, never Wasmtime distribution versions or
profile digests.

In a project that declares a WASI assemble graph, a rejected selection fails
while Gradle configures that graph and is reported as `[WLAOT100]`; the AOT
build and check task actions still validate their own evaluated inputs. Either
way, validation completes before compiler assets are downloaded or a package is
signed. The repository root `aot-compatibility.json` is the only manually
maintained AOT catalog. Run `./scripts/wasmline aot sync` after changing it; the
command validates the entries and creates the packaged lock used by build tools.
A generation number orders catalog entries. Native loading still matches the
backend-specific profile ID reported by the linked engine.

After a successful assemble, `wasmlineCheckAotCompatibility` compares the local
selection with the latest stable catalog and writes
`build/reports/wasmline/aot-compatibility-check.json`. The check has a five-
second network deadline and logs a warning even when no generation is missing.
Set `suppressCompatibilityWarning.set(true)` only after reviewing the report;
it hides the warning but does not skip the check or change AOT files.

`targets` controls generated files. Use `pulley32` or `pulley64` for PWASM and a
platform target such as `x86_64-linux` for CWASM. iOS uses `pulley64` only.
Compiler archives are resolved from the generated lock and cached under
`~/.wasmline/toolchains/wasmtime/compiler-assets/sha256/`. `autoDownload` only
permits downloads whose digests are present in that lock.

## Raw Export ABI

`CORE_WASM + RAW_EXPORT` packages declare their numeric ABI with
`manifest.rawAbi`. The signed contract is read by native and Web loaders.

```kotlin
import crow.wasmline.RawAbiMetadata
import crow.wasmline.RawExport
import crow.wasmline.RawExportKind
import crow.wasmline.RawFunctionSignature
import crow.wasmline.RawValueType
import crow.wasmline.WasmlineExecutionModel
import crow.wasmline.WasmlineInvocationProtocol

wasmline {
    manifest {
        executionModel = WasmlineExecutionModel.CORE_WASM
        invocationProtocol = WasmlineInvocationProtocol.RAW_EXPORT
        exportName = "add_i32"
        rawAbi = RawAbiMetadata(
            exports = listOf(
                RawExport(
                    name = "add_i32",
                    kind = RawExportKind.FUNCTION,
                    signature = RawFunctionSignature(
                        parameters = listOf(RawValueType.I32, RawValueType.I32),
                        results = listOf(RawValueType.I32),
                    ),
                ),
            ),
        )
    }
}
```

Do not put parameter or result types in `contractMetadata`. The AOT task
sorts and normalizes `rawAbi` before it writes cache inputs and build records.

## Build and Serve

```bash
./gradlew wasmlineAssembleDebug
./gradlew wasmlineAssembleRelease
./gradlew wasmlineServerDeploy
```

For a multi-module build, include the module path, for example
`./gradlew :plugin:wasmlineAssembleRelease`.

An assemble task writes one signed manifest for all selected profiles and
targets. Core Web `.wasm` is stored once. The output paths are:

```text
build/wasmline/output/{pluginId}-{version}/
build/wasmline/dist/{pluginId}-{version}.zip
```

```kotlin
import crow.wasmline.gradle.WasmlineBuildVariant

wasmline {
    server {
        host = "0.0.0.0"
        port = 8080
        deployVariant = WasmlineBuildVariant.RELEASE
    }
}
```

`deployVariant` defaults to `DEBUG`. The server serves the selected package
until the task stops.

## Registered Tasks

| Task | Purpose |
|---|---|
| `wasmlineAotBuildDebug` | Build Debug AOT profiles for the configured targets |
| `wasmlineAotBuildRelease` | Build Release AOT profiles for the configured targets |
| `wasmlineCheckAotCompatibility` | Compare local AOT profiles with the latest catalog |
| `wasmlineAssembleDebug` | Sign the Debug manifest and package files |
| `wasmlineAssembleRelease` | Sign the Release manifest and package files |
| `wasmlineServerDeploy` | Build and serve a package directory |
| `generateWasmlineManifestKeyPairEd25519` | Generate an Ed25519 manifest key pair |
| `wasmlineDownloadComponentTools` | Download locked `wit-bindgen`, `wasm-tools`, and the WASI adapter |
| `wasmlineComponentizeDebug` | Create or validate the Debug Component input |
| `wasmlineComponentizeRelease` | Create or validate the Release Component input |
| `wasmlineGenerateWitBindings` | Generate guest bindings when no Component input is supplied |
| `wasmlineGenerateHostWitBindings` | Generate host facades when host bindings are enabled |
| `wasmlineGenerateTrustedKeys` | Generate the configured Host public-key trust object |

Raw Component Wasm is a build input. It is not published as a browser artifact.

## Reproducible Output

Before signing, Gradle builds every AOT artifact selected by the configured
profiles and targets. A failed compile, digest check,
signature, or ZIP replacement leaves the previous package directory and ZIP
unchanged. Set `manifest.buildTimestamp`, commonly from `SOURCE_DATE_EPOCH`,
when reproducible bytes are required.
