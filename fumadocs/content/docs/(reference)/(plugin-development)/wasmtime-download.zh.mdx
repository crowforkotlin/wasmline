# Wasmtime AOT 兼容性

Native Wasmtime 不能反序列化所有 AOT 文件。每当 engine 的序列化产物契约发生
变化，Wasmline 就记录一个不可变的 AOT generation。一个 generation 对应一个
fork distribution，以及一组 Cranelift/Pulley profile。

Profile 描述包含 fork 的 Wasmtime `x.y.z`、source revision、产物格式、编译器
设置、engine 设置和 backend。规范化后的 JSON 会计算为
`sha256:<digest>` profile ID。即使使用同一个 fork release，Cranelift 和 Pulley
也有不同的 ID。

## 版本名称

上游 Wasmtime 使用 `x.y.z` 版本。fork distribution 使用四段版本 `x.y.z.v`。
例如，`major.minor.patch.fork` 表示基于 `major.minor.patch` 的 fork distribution。
fork 发布新 distribution 时会增加第四段；该数字本身不能证明 AOT 兼容。

插件作者通过 `aotCompatibility { generations(...) }` 选择本地 Wasmline release 的
覆盖范围；省略该 block 会选择 packaged catalog 中保留的全部 generation。他们不填写
Wasmtime distribution 版本。catalog 会把选中的 Wasmline 版本解析为所需的 profile ID
和 compiler asset。

## 配置构建

```kotlin
import crow.wasmline.gradle.WasmtimeTarget

wasmline {
    wasmtime {
        aotCompatibility {
            generations("latest")
        }
        targets = listOf(
            WasmtimeTarget.PULLEY_64,
            WasmtimeTarget.X86_64_LINUX,
        )
        autoDownload.set(true)
    }
}
```

`generations("latest")` 保持“只编译 packaged catalog 当前 Wasmline 版本”的范围。
省略 block、留空或只配置 `suppressCompatibilityWarning` 时，会编译本地 catalog 中保留
的全部 generation；第一次显式调用替换该默认值，之后的调用形成并集：

```kotlin
wasmline {
    wasmtime {
        aotCompatibility {
            generations("1.0.0")
            generations(from = "1.0.1", through = "latest")
            suppressCompatibilityWarning.set(false)
        }
    }
}
```

| 调用 | 选择内容 |
|---|---|
| `generations("1.0.0")` | 包含该稳定 Wasmline 版本的 generation |
| `generations("latest")` | packaged catalog 当前 Wasmline 版本所在的 generation |
| `generations(from = "1.0.1", through = "latest")` | 与闭区间相交的全部 generation |
| 省略 `aotCompatibility` | 本地 catalog 中保留的全部 generation |

两端都必须是稳定的 `x.y.z` Wasmline 版本，并位于 catalog 的
`minimumSupportedWasmlineVersion`..`currentWasmlineVersion` 边界内；`through` 也可以
是 `"latest"`。倒置区间、以符号值作为区间起点、越界 endpoint 或其他不可用的选择都
会在下载 compiler 文件前失败，不会被裁剪或静默缩小。选择基于 Wasmline 版本：
profile 摘要和 fork distribution 版本永远不是用户输入。仓库根目录的
`aot-compatibility.json` 是唯一人工维护的 catalog。修改后执行
`./scripts/wasmline aot sync`；该命令会校验条目并生成构建工具使用的 packaged
lock。generation 只是目录中的顺序编号，不是运行时凭据。加载仍要求与已链接
engine 报告的 profile ID 完全匹配。

## Compiler Asset 缓存

`versions.json` 保存项目和工具链的标量版本；AOT 历史只保存在
`aot-compatibility.json`。`aot sync` 会生成
`META-INF/wasmline/aot/aot-compatibility-lock.json` 以及供构建工具使用的相同
公共资源。

Compiler archive 按执行构建的机器选择。每个 archive 和解压后的 executable 都
锁定 SHA-256。共享缓存位置为：

```text
~/.wasmline/toolchains/wasmtime/compiler-assets/
└── sha256/{prefix}/{archiveDigest}/{buildHost}/
```

同一个 archive 可以服务两个 backend，并且只下载一次。设置
`autoDownload = false` 后，所有所需文件必须已存在并通过摘要校验。不接受任意
compiler executable 或目录。

使用以下命令查看 catalog：

```bash
./wasmline-cli/cli.sh aot-profiles list
./wasmline-cli/cli.sh aot-profiles describe sha256:<digest>
```

## Target 规则

`pulley32` 生成 32 位 PWASM，`pulley64` 生成 64 位 PWASM。PWASM 不是 raw
WebAssembly，pointer width 必须匹配。iOS 使用 `pulley64`。

CWASM 必须同时匹配 engine 的 Cranelift profile、操作系统、架构、pointer width
和 CPU feature profile。只有不存在匹配 CWASM，且 runtime 报告匹配的 Pulley
profile 并支持 PWASM 时，Cranelift runtime 才能使用 PWASM。CWASM 下载失败、摘要
错误、大小错误或反序列化失败时，不会静默改用 PWASM。

Web 不使用 Wasmtime profile。无论 native profile 有多少，Core package 只保存一份
供浏览器使用的 raw `.wasm` variant。

## 兼容性警告

`wasmlineCheckAotCompatibility` 在 Debug 或 Release assemble 成功后运行。它在
五秒网络等待上限内，将本地 catalog 与 GitHub 最新稳定 catalog 比较，并把 JSON
报告写入 `build/reports/wasmline/`。generation 不足和 generation 相同都会有明确
日志。确认报告后才应设置 `suppressCompatibilityWarning.set(true)`；该设置只改变
日志，不改变构建结果。

## 增加 Generation

只有 Wasmline engine release 改变 AOT contract 时，维护者才增加 generation。在
`versions.json` 更新 Wasmtime 标量版本，在 `aot-compatibility.json` 追加新的范围，
然后执行：

```bash
./scripts/wasmline versions sync
./scripts/wasmline aot sync
./scripts/wasmline aot check
```

新增 fork distribution 时，`aot sync` 会解析准确的
`crowforkotlin/wasmtime` release 和 source revision，校验 `SHA256SUMS`，并临时
下载所需 CLI archive 记录 compiler 摘要。已有 distribution 保持离线。不要手动
编辑生成的 lock。
