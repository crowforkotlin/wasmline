# CLI Reference

Run the CLI from ``. The repository launcher builds the
CLI distribution and forwards its arguments:

```bash
./wasmline-cli/cli.sh <command> [options]
```

## Commands

| Command | Result |
|---|---|
| `build` | Compile the selected AOT profiles, sign one manifest, and create an offline ZIP |
| `compile` | Compile the selected AOT profiles and write `aot-build-record.json` |
| `manifest` | Sign an existing build record |
| `generate-key-pair` | Generate the Ed25519 key pair accepted by the manifest format |
| `aot-profiles list` | List catalog profiles and their IDs |
| `aot-profiles describe <id>` | Show one profile descriptor and its build hosts |
| `componentize` | Create or inspect the raw Component used as AOT input |
| `tools download` | Download locked Component tools |
| `wit generate` | Generate WIT bindings |
| `component validate` | Validate a Component |
| `component inspect` | Print a Component's WIT |

The CLI does not accept the removed `download` command, a `--wasmtime` directory,
or an arbitrary compiler executable. AOT compilers come from the digest-locked
catalog. The removed `--aot-compatibility`, `--aot-version-range`, and
`--min-sdk` options have no aliases either; AOT coverage is selected only through
`--aot-generations`.

## Build a Package

```bash
./wasmline-cli/cli.sh generate-key-pair --save

./wasmline-cli/cli.sh build \
  --input plugin.wasm \
  --aot-generations latest \
  --target pulley64 \
  --target x86_64-linux \
  --auto-download \
  --plugin-id com.example.plugin \
  --version 1.0.0 \
  --build-timestamp 0 \
  --key build/wasmline/keys/ed25519_private.key
```

`--aot-generations` is repeatable. Each value is a stable `x.y.z` Wasmline
version, the exact lowercase token `latest`, or a closed `FROM..THROUGH` range
whose `FROM` is a stable version and whose `THROUGH` is a stable version or
`latest`. Values are exact tokens: the CLI does not split comma lists, trim
whitespace, accept open ranges, or accept more than one `..` delimiter.
`latest` refers to the Wasmline version of the catalog packaged into the CLI,
not the newest remote release. Omitting the option selects every generation
retained in that local catalog; repeated values contribute to one union:

```bash
./wasmline-cli/cli.sh compile \
  --input plugin.wasm \
  --aot-generations 1.0.0 \
  --target pulley64

./wasmline-cli/cli.sh compile \
  --input plugin.wasm \
  --aot-generations 1.0.0 \
  --aot-generations 1.0.1..latest \
  --target x86_64-linux
```

Both endpoints of a range must lie inside the catalog's
`minimumSupportedWasmlineVersion`..`currentWasmlineVersion` bounds. For the
catalog retained today, `--aot-generations 1.0.0..latest` therefore selects the
same generations as omitting the option. An empty token, an inverted range, a
symbolic range start such as `latest..1.0.1`, or an out-of-range endpoint is
rejected without clipping to the intersecting part.
Different values that resolve to the same generation, and reused backend
profiles, are deduplicated and sorted deterministically. The CLI resolves
catalog bounds and profiles once before any tool download, Component
preparation, compilation, or signing, so selection errors surface before a
package is written. These inputs are Wasmline versions that select catalog
generations; the CLI still does not accept a free-form Wasmtime version or
profile ID.

## Raw Export ABI

For `CORE_WASM + RAW_EXPORT`, pass a JSON file with the same schema as the
Gradle `RawAbiMetadata` value:

```json
{
  "version": 1,
  "exports": [
    {
      "name": "add_i32",
      "kind": "FUNCTION",
      "signature": {
        "parameters": ["I32", "I32"],
        "results": ["I32"]
      }
    }
  ],
  "imports": [],
  "memoryExport": "memory",
  "requiredFeatures": []
}
```

```bash
./wasmline-cli/cli.sh build \
  --input plugin.wasm \
  --execution-model CORE_WASM \
  --invocation-protocol RAW_EXPORT \
  --export-name add_i32 \
  --raw-abi-metadata raw-abi.json \
  --target pulley64 \
  --key build/wasmline/keys/ed25519_private.key
```

The plugin-core codec rejects unknown fields and invalid types, then sorts the
export, import, and feature lists before creating the build record.
`contractMetadata` is for other annotations and does not replace the raw ABI.

## Output Layout

```text
build/wasmline/
├── output/com.example.plugin-1.0.0/
│   ├── manifest.wlm
│   ├── artifacts/sha256/
│   │   ├── 4f/4f13c7...a920.cwasm
│   │   ├── 91/91aa42...c810.wasm
│   │   └── b8/b8072d...0f31.pwasm
│   └── debug/
│       ├── manifest.json
│       ├── aot-build-record.json
│       └── artifact-index.json
├── dist/com.example.plugin-1.0.0.zip
└── keys/
    ├── ed25519_private.key
    └── ed25519_public.key
```

One signed manifest describes all selected profiles. A Core package stores its
Web `.wasm` once, outside the native profile list. A Component's raw Wasm is
only a build input. Identical bytes share one content-addressed file.

The offline ZIP contains the complete artifact set. A remote loader verifies the
manifest, chooses one variant, and downloads only that file; it does not fetch
the ZIP.

Compilation and signing use staging directories. A failed compile, signature,
or ZIP replacement leaves the previous package directory and ZIP unchanged.

The Gradle-only `wasmlineCheckAotCompatibility` task compares the local catalog
with the latest stable release. CLI compilation stays offline and reads only its
packaged catalog.
