## 执行栈

Wasmline 从 `commonMain` 和 `hostMain` 暴露相同的公共 API，再按目标选择后端。
Android、iOS、macOS、Linux 和 Windows 使用 `wasmline-core`（C/C++，由 Zig 0.16.0
构建）调用 Wasmtime C API。Kotlin/JS 与 Kotlin/WasmJS 使用浏览器 WebAssembly API，
不会加载 Wasmtime。

### 原生目标栈 — Android · iOS · macOS · Linux · Windows

```text
Host Application  (commonMain / hostMain)
        │
        │  module.link<T>()      — IR-synthesized typed outbound proxy
        │  module.bind(impl)     — IR-synthesized inbound dispatch registration
        │
        ▼
Platform actual  (jniMain / nativeMain)
        │  JNI external declarations          — JVM / Android
        │  Kotlin/Native C Interop (.def)     — iOS、macOS、Linux、Windows
        ▼
wasmline-core  (C/C++ · Zig 0.16.0)
        │  Engine.cpp               — 创建 engine 和选择 backend
        │  Module.cpp/Component.cpp — 反序列化 AOT 产物并缓存
        │  Session variants         — Service、Raw Export 与 Component 调用
        │  Api.cpp                  — JNI / C Interop 调用（load、invoke、setOutbound、release）
        ▼
wasmtime C-API  v50.0.0
        │  Sandboxed execution; hardware-accelerated AOT; per-session memory isolation
        ▼
Precompiled artifact  (.cwasm — Cranelift 原生 AOT  |  .pwasm — Pulley 字节码；Core 或 Component 需独立声明)
```

Engine 和产物格式分别选择。Cranelift runtime 只在 profile 与完整 target identity
匹配时加载 CWASM。只有不存在匹配 CWASM，且 runtime 报告匹配 Pulley profile 时，
才能使用 PWASM。Pulley runtime 只接受 PWASM。iOS 使用 `pulley64` PWASM。

### Web 目标栈 — Kotlin/JS · Kotlin/WasmJS

```text
Host Application  (commonMain / hostMain)
        │
        │  module.link<T>()      — IR 生成的 proxy
        │  module.bind(impl)     — IR 生成的分发注册
        │
        ▼
webMain / jsMain / wasmJsMain
        │  WasmlineWeb · WebWasmArtifacts · WebWasmPlugin
        ▼
Inline JS runtime  (Kotlin js() interop — no external .js files emitted)
        │
        ▼
Browser WebAssembly API  (WebAssembly.Module + WebAssembly.Instance)
        │
        ├── Import namespace: wasi_snapshot_preview1
        │     fd_write         — UTF-8 stdout/stderr 经 WasmlineLog 或 println 输出
        │     random_get       — Kotlin Random.nextBytes
        │     clock_time_get   — 将 Date.now() 的毫秒值转换为纳秒值
        │
        └── Import namespace: env  (Wasmline bridge protocol)
              bridge_inbound_copy_params     — write action + payload into Wasm linear memory
              bridge_inbound_set_response    — extract response bytes from Wasm linear memory
              bridge_outbound_call_host      — synchronous plugin-to-host dispatch callback
              bridge_outbound_get_response   — copy oversized outbound response to caller buffer
        │
        ▼
Plugin binary  (raw .wasm — 先通过 Fetch 异步预取，再从字节缓存同步加载)
```

## Manifest 与产物选择

一个签名 manifest 描述插件 contract 和全部可用产物：

```text
SignedManifest
└── exact signed payload bytes
    └── WasmlineManifest
        ├── runtimeContract
        ├── aotCompatibilityProfiles
        └── artifactTargets
            └── variants (profile IDs, SHA-256, size)
```

Manifest 格式和签名算法固定。Loader 先检查 format version、解析 trusted key，
对原始 payload 字节执行 Ed25519 校验，再解码和验证 manifest。产物路径使用摘要
和扩展名：

```text
artifacts/sha256/{digest-prefix}/{digest}.{extension}
```

Native engine 报告支持的格式、backend AOT profile ID、Wasmline release、bridge ABI、
操作系统、架构、pointer width 和 CPU feature。Loader 只构建一次 profile-ID map，
再扫描 manifest 条目，不扫描 package 目录。

远程加载先请求 `manifest.wlm`，选择一个 variant，再流式下载并校验声明的 size 和
SHA-256。不会下载离线 ZIP。Core Web `.wasm` variant 与 native profile 无关，只
保存一次。Component raw Wasm 仍是构建输入。

缓存的 manifest 字节在每次加载时都会重新验签，但
`WasmlineLoadOptions.manifestTtlMs` 只是新鲜度窗口，既不是签名过期时间，也不提供
防回滚保证；命中新鲜缓存时仍可在不访问网络的情况下返回该包。`maxCacheBytes` 以
best-effort 方式约束内置文件缓存：受保护路径、未达到最小淘汰年龄的条目，以及清理
过程中的任何错误都会被跳过，因此目录可能暂时超出该上限。自定义 `WasmlineCache`
自行负责其容量策略。

## 执行模型

运行时根据 `WasmlineArtifactDescriptor` 选择后端。文件扩展名不会决定执行模型。

| 执行模型 | 调用协议 | 运行时边界 | Core 响应帧 |
|---|---|---|---|
| `CORE_WASM` | `WASMLINE_SERVICE` | `Session`、action 路由和线性内存 | 使用 |
| `CORE_WASM` | `RAW_EXPORT` | `CoreWasmModule`/`CoreWasmSession`、exports、同步 imports 与线性内存 | 不使用 |
| `COMPONENT_MODEL` | `WASMLINE_SERVICE` | `ComponentSession` 和固定 `wasmline.wit` 请求格式 | 不使用 |
| `COMPONENT_MODEL` | `COMPONENT_EXPORT` | `ComponentSession` 和 Component Model 值 | 不使用 |

`WASMLINE_SERVICE` 选择 Wasmline 服务 API。与 `CORE_WASM` 组合时，响应字节使用固定
的 `WLMF` 标记和一个字节的 `frameVersion`（当前为 `1`）；与 `COMPONENT_MODEL` 组合
时，使用固定的 `wasmline:service@1.0.0` WIT 请求格式和 Canonical ABI。执行模型决定
实际使用的表示方式。

Raw Export 使用显式声明的数值 ABI。当前公共 raw 值包括 `i32`、`i64`、`f32` 和 `f64`。Export signature、同步 import、memory 与所需 feature 保存在签名后的 `runtimeContract.rawAbi` 模型中，不编码到自由格式 metadata。该路径不分配或解析 Core 响应帧。

Component Model 调用通过 Wasmtime Component Model API 反序列化预编译的 Component
`.cwasm` 或 `.pwasm`。该路径使用 typed Component value，不要求 Core 线性内存、
`__wasmline_wasi_entry` 或 Core 响应帧。Loader 不会运行 `wit-bindgen`、`wasm-tools`
或 `wasmtime compile`；Gradle 和 CLI 构建任务会在加载前完成这些步骤。
`contractMetadata` 可以记录调用信息用于校验和文档，但不是编译器输入。

四种组合都返回相同的成功或失败结构。未绑定的服务 action 返回
`ACTION_NOT_BOUND`，不是空的成功 payload。Core Service 通过响应帧传递失败，Raw
Export 和 Component Model 返回 typed failure。只有调用无效、运行时状态不可恢复或
无法创建结果时才抛出异常。

Native Core Service 会拒绝同一线程上对正在调用的 session 的同步重入。该检查在
session mutex 之前执行，因此 `A -> A` 与 `A -> B -> A` 都返回 `REENTRANT_CALL`
而不是死锁；从回调中调用另一个未激活的 session 仍然允许。Guest 提供的 `memory32`
range 会在创建任何 view 或执行拷贝之前按当前线性内存校验；负数 guest 长度以
`CORE_TRAP` 触发。Host 自身的 payload 长度只有在通过 `INT32_MAX` 检查之后才会收窄
为有符号 `i32` bridge ABI。

Web 实现同时支持 `CORE_WASM + WASMLINE_SERVICE` 与
`CORE_WASM + RAW_EXPORT`，通过浏览器的 `WebAssembly.Module` 和
`WebAssembly.Instance` API 执行。Raw session 直接调用数值 export，在实例化前注册同步
import，并提供有边界检查的线性内存访问；它不使用 Service 响应帧。Component Model
typed 调用仍仅由 native 提供。Web 与 native 共用 Core ABI 契约，但保留不同后端：Web
使用 JS/WasmJS binding 和 raw `.wasm`，native 使用 Wasmtime bridge 与
`.cwasm`/`.pwasm` AOT 产物。

Web Raw 的结果结构错误复用既有 Core 错误码：产出的结果数量与声明签名不符时返回
`ARGUMENT_COUNT_MISMATCH`；产出值的 JavaScript 表示与声明类型矛盾时返回
`ARGUMENT_TYPE_MISMATCH`。普通 JS number 不携带 wasm 类型，因此 `i32`、`f32` 与
`f64` 之间的错误声明无法检测；`i64` 失配则可通过 `bigint` 识别。真正的 guest trap
仍为 `WASM_TRAP`，失败的 host import 保留其自身错误码。`RawMemory` 的 offset 是有
符号 32 位 JS 索引，因此只接受 `0..Int.MAX_VALUE`；length 与当前内存大小分别校验，
接近 2 GiB 的 length 既未验证也不承诺可用。`CoreWasmCapabilities` 是受支持 feature
集的声明，而不是对浏览器的运行时探测：当前所有后端都声明支持 `multiValue`、`i64`、
`bulkMemory` 与 `referenceTypes`，并声明不支持 `simd` 与 `threads`。

Component instance 与 resource wrapper 不支持并发使用。调用方必须串行执行完整操作，
包括生成代码中的参数准备与所有权转移。`transferToComponent()` 会在 native 调用前立即
消费 `own<T>` wrapper；后续参数准备、校验或 guest 执行失败不会恢复 wrapper。显式
resource `close()` 则区分两种结果：拒绝 drop 时 wrapper 保持打开；已经消费引用后，
即使析构失败，wrapper 也保持关闭。Guest 调用是同步的；关闭 instance 或取消 host
协程不能中断正在执行的 guest 调用。

## 模块依赖关系图

```text
wasmline-cli ───────────► wasmline-plugin-core ───────► wasmline-loader ──► wasmline
wasmline-gradle-plugin ─► wasmline-plugin-core
        │
        └───────────────► wasmline-kotlin-plugin  (编译期 IR 变换)

wasmline ◄──── native runtime assets ──── wasmline-engine-cranelift / wasmline-engine-pulley
wasmline-network-ktor / wasmline-network-okhttp ──────► wasmline-loader
wasmline-core (C/C++) ◄──── JNI / Native C Interop ─── wasmline
wasmline-bom ── strict same-version constraints ──────► published Wasmline modules
```

network、cache、trusted key 和 load request API 都属于 `wasmline-loader`。Ktor 与
OkHttp 实现它的 suspend network SPI，核心 runtime 不依赖 HTTP engine。只有远程缓存
未命中时才需要其中一个模块。Ktor 覆盖 JVM、Android、Apple、Linux 和 Windows Native；
OkHttp 覆盖 JVM 与 Android。浏览器 raw `.wasm` 使用 `WasmlineWeb.prefetch()`。

## 仓库目录结构

```text
wasmline/                               # 仓库根目录
├── wasmline/                           # Gradle KMP 模块：公共 runtime 与各后端 actual
│   ├── src/
│   │   ├── commonMain/                 # 平台无关 contract、值类型与 bridge 抽象
│   │   ├── hostMain/                   # Host API：Wasmline、load state、Core 与 Component 调用
│   │   ├── jniMain/                    # JVM / Android actual — JNI 声明与 native 辅助代码
│   │   ├── nativeMain/                 # Kotlin/Native actual 与 C Interop
│   │   ├── webMain/                    # 共享 Web host runtime 与 expect binding contract
│   │   ├── jsMain/                     # Kotlin/JS binding actual
│   │   ├── wasmJsMain/                 # Kotlin/WasmJS binding actual
│   │   └── wasmWasiMain/               # Core 与 Component Service guest hook
│   ├── build.zig                       # 桌面 JNI 库的 Zig 构建
│   └── build.gradle.kts                # 目标、native bridge 任务与发布配置
├── wasmline-core/                      # C/C++ Wasmtime bridge（Engine、Module、Session、Api）
├── wasmline-loader/                    # Load request/options、cache/network SPI 与 .wlm 校验
├── wasmline-engine-cranelift/          # Cranelift 分发：预编译 JVM JNI 与 Native archive
├── wasmline-engine-pulley/             # Pulley 分发：预编译 JVM JNI 与 Native archive
├── wasmline-android/                   # Android 库；预编译 JNI 由 engine 模块提供
├── wasmline-kotlin-plugin/             # Kotlin IR compiler plugin — 生成 bridge 类和重写调用点
├── wasmline-gradle-plugin/             # Gradle 配置 DSL 与任务，使用 compiler plugin 和 plugin-core
├── wasmline-plugin-core/               # 共享 Core/Component 构建、签名、打包与工具链逻辑
├── wasmline-cli/                       # plugin-core 与 loader 操作的 CLI adapter
├── wasmline-network-ktor/              # Ktor loader 网络 adapter
├── wasmline-network-okhttp/            # OkHttp loader 网络 adapter
├── wasmline-bom/                       # 强制所有 Maven 模块使用同一版本
├── wasmline-native-test-fixtures/      # Native AOT fixture 源、生成任务与 fixture 索引
├── wasmline-plugin-test/               # 独立的 Gradle 构建，用于 plugin 端到端集成测试
├── wasmline-build-logic/               # included build，提供共享 Gradle convention plugin
├── samples/
│   ├── minimal-library/                # 两个 minimal 示例共用的 UI 与加载库
│   ├── minimal-raw-export/             # Raw export 示例，含 Android、Desktop、JS 与 WasmJS host
│   ├── minimal-service/                # Typed service 示例，含 Android、Desktop、JS 与 WasmJS host
│   └── multiplatform-app/              # 多平台 host、示例 app 与跨语言 guest
├── iosApp/                             # iOS framework 的 Xcode host 应用
├── scripts/                            # 环境、资产、lint、native 构建与版本同步命令
├── build/                              # Root 构建输出；build/platforms/v<wasmtime-release>/ 存放 Wasmtime 资产
├── docs/                               # 技术说明：runtime 思维导图、IR fixture 与 native 加载
└── fumadocs/                           # 文档站点（Next.js + Fumadocs）
```
