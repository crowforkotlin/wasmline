# Testing

Wasmline tests are split by the boundary they validate. Run the repository preflight once per session, immediately before the first validation required after changing Wasmline files. Skip it when no Wasmline file change requires validation:

```bash
./scripts/wasmline doctor
```

## Test Matrix

| Area | Module | Main coverage | Command |
|---|---|---|---|
| Common runtime | `wasmline` | response frames, descriptors, and serialization | `./gradlew :wasmline:jvmTest` |
| Host runtime | `wasmline` | local artifact bridge, typed raw/component invocation, and host API compilation | `./gradlew :wasmline:jvmTest` |
| Native Wasmtime | `wasmline` | JNI lifecycle, artifact loading, raw exports, component exports | `./gradlew :wasmline:nativeAotJvmTest` |
| Kotlin/JS | `wasmline` | WebAssembly imports, values, memory, and exports | `./gradlew :wasmline:jsBrowserTest` |
| Kotlin/WasmJS | `wasmline` | WebAssembly imports, values, memory, and exports | `./gradlew :wasmline:wasmJsBrowserTest` |
| Kotlin/WasmWasi | `wasmline` | WASI runtime integration | `./gradlew :wasmline:wasmWasiNodeTest` |
| Loader | `wasmline-loader` | manifests, signatures, local and remote package resolution | `./gradlew :wasmline-loader:jvmTest` |
| CLI | `wasmline-cli` | platform detection and key generation | `./gradlew :wasmline-cli:test` |
| IR box | `wasmline-kotlin-plugin` | generated bridge behavior, compiler validation, and FIR/IR snapshots | See [Compiler Plugin](/en/docs/compiler-plugin) |

Run all JVM-facing checks from `wasmline-multiplatform/`:

```bash
./gradlew :wasmline:jvmTest \
  :wasmline-loader:jvmTest \
  :wasmline-cli:test \
  :wasmline-kotlin-plugin:generateTests \
  :wasmline-kotlin-plugin:test
```

Native Wasmtime tests load the Cranelift JNI library from `wasmline-engine-cranelift/src/jvmMain/resources/jni/`. The ordinary `jvmTest` task excludes tests that require serialized AOT artifacts. `nativeAotJvmTest` first runs `:wasmline-native-test-fixtures:assembleNativeTestFixtures`, passes its fixture index to the test process, and then runs every native AOT integration test. A missing, changed, or incorrectly indexed artifact fails the task.

## Native AOT Fixtures

Fixture source files are committed under `wasmline-native-test-fixtures/src/fixtures/`. The module generates `.cwasm` or `.pwasm` files in its `build/` directory; these binary files must not be committed or supplied through test environment variables.

From the repository root, build the Cranelift JNI library before the Linux JVM check. The fixture task generates the host-specific Cranelift target and the portable `pulley64` target:

```bash
./scripts/wasmline jni build --engine cranelift
cd wasmline-multiplatform
rustup target add wasm32-wasip2
./gradlew :wasmline:nativeAotJvmTest \
  -Pwasmline.native.fixtures.targets=x86_64-linux,pulley64 \
  --no-daemon
```

The fixture index records the fixture ID, execution model, invocation protocol, artifact format and backend, requested and normalized targets, AOT profile ID, relative path, file size, and SHA-256 digest. The JVM suite loads a `raw-export-basic` `pulley64` PWASM fixture through the Cranelift native library and invokes its `add` export. The test helper selects the entry whose target and profile match the linked native runtime, then verifies the file again before copying it to a temporary path.

iOS simulator tests use only the portable Pulley target. Run the following on macOS from the repository root:

```bash
./scripts/wasmline wasmtime download --target ios-simulator-arm64 --engine pulley
cd wasmline-multiplatform
rustup target add wasm32-wasip2
./gradlew :wasmline:iosSimulatorArm64Test \
  :wasmline-loader:iosSimulatorArm64Test \
  -Pwasmline.native.fixtures.targets=pulley64 \
  --no-daemon
```

An iOS test fails when the index is absent, when the selected fixture does not match the requested execution model, invocation protocol, Pulley backend, `pulley64` target, `.pwasm` suffix, file size, or linked AOT profile. Rust resource fixtures require the `wasm32-wasip2` target before assembly.

## IR Test Rules

Active IR fixtures live in `wasmline-kotlin-plugin/testData/box/`:

- `box/*.kt` validates generated bridge behavior through `fun box(): String`.
- `test-gen/` and FIR/IR snapshots are generated outputs.

Only edit the source fixture. Regenerate runners and snapshots with:

```bash
./gradlew :wasmline-kotlin-plugin:generateTests
./gradlew :wasmline-kotlin-plugin:test \
  --tests 'crow.wasmline.kotlin.runners.JvmBoxTestGenerated'
```

Do not hand-edit `test-gen/`, `*.fir.txt`, or `*.fir.ir.txt`.

The repository retains an `AbstractJvmDiagnosticTest` scaffold, but its generator model is disabled. There is no active `testData/diagnostics/` directory or `JvmDiagnosticsTestGenerated` runner.

## Version Verification

`versions.json` is the source of truth for project, sample-plugin, Wasmtime, Kotlin, ktlint, Dokka, AGP, Zig, and JBR versions. The synchronizer updates all managed build files, scripts, documentation, and CI fallbacks in one operation:

```bash
./scripts/wasmline versions sync
./scripts/wasmline versions sync \
  --set wasmtime_version=48.0.1 \
  --set wasmtime_release_version=48.0.1.1
./scripts/wasmline versions check
python3 scripts/tests/test_versions.py

# Inspect or update the pinned standalone Kotlin formatter.
./scripts/wasmline versions check-ktlint
./scripts/wasmline versions update-ktlint
```

Run `versions sync` after editing `versions.json`, or use `--set` to update the manifest and synchronize in one command. Local Kotlin lint and CI both resolve the pinned `ktlint_version`; they do not float to an unreviewed release. The weekly `Update ktlint` workflow opens or updates a pull request when a newer stable release is available. The test command runs an independent regression suite and does not update versions.

## Kotlin Documentation Style

Kotlin declarations in runtime and test sources use KDoc (`/** ... */`) for API and test intent. Keep comments required by external test formats, such as `// WITH_STDLIB`, unchanged. Prefer a focused KDoc on the class or test function over narration inside the assertion body.
