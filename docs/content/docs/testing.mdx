# Testing

Wasmline tests are split by the boundary they validate. Run the repository preflight once before any Gradle command:

```bash
bash ./scripts/doctor.sh
```

## Test Matrix

| Area | Module | Main coverage | Command |
|---|---|---|---|
| Common runtime | `wasmline` | response frames, descriptors, and serialization | `./gradlew :wasmline:jvmTest` |
| Host runtime | `wasmline` | local artifact bridge, typed raw/component invocation, and host API compilation | `./gradlew :wasmline:jvmTest` |
| Native Wasmtime | `wasmline` | JNI lifecycle, artifact loading, raw exports, component exports | `./gradlew :wasmline:jvmTest` |
| Kotlin/JS | `wasmline` | WebAssembly imports, values, memory, and exports | `./gradlew :wasmline:jsBrowserTest` |
| Kotlin/WasmJS | `wasmline` | WebAssembly imports, values, memory, and exports | `./gradlew :wasmline:wasmJsBrowserTest` |
| Kotlin/WasmWasi | `wasmline` | WASI runtime integration | `./gradlew :wasmline:wasmWasiNodeTest` |
| Loader | `wasmline-loader` | manifests, signatures, local and remote package resolution | `./gradlew :wasmline-loader:jvmTest` |
| CLI | `wasmline-cli` | platform detection and key generation | `./gradlew :wasmline-cli:test` |
| IR box/diagnostics | `wasmline-kotlin-plugin` | generated bridge structure and compiler validation | See [Compiler Plugin](/en/docs/compiler-plugin) |

Run all JVM-facing checks from `wasmline-multiplatform/`:

```bash
./gradlew :wasmline:jvmTest \
  :wasmline-loader:jvmTest \
  :wasmline-cli:test \
  :wasmline-kotlin-plugin:generateTests \
  :wasmline-kotlin-plugin:test
```

Native Wasmtime tests require the native library under `wasmline/src/jvmMain/resources/jni/`. The CI pipeline builds that library before running `:wasmline:jvmTest`. Web tests do not require native Wasmtime assets, but browser tests require a Chrome-compatible runner.

## IR Test Rules

IR fixtures live in `wasmline-kotlin-plugin/testData/`:

- `box/*.kt` validates generated bridge behavior through `fun box(): String`.
- `diagnostics/*.kt` validates compiler diagnostics and directives.
- `test-gen/` and FIR/IR snapshots are generated outputs.

Only edit the source fixture. Regenerate runners and snapshots with:

```bash
./gradlew :wasmline-kotlin-plugin:generateTests
./gradlew :wasmline-kotlin-plugin:test \
  --tests 'crow.wasmline.kotlin.runners.JvmBoxTestGenerated'
./gradlew :wasmline-kotlin-plugin:test \
  --tests 'crow.wasmline.kotlin.runners.JvmDiagnosticsTestGenerated'
```

Do not hand-edit `test-gen/`, `*.fir.txt`, or `*.fir.ir.txt`.

## Version Verification

`scripts/versions.json` is the source of truth for project, sample-plugin, Wasmtime, Kotlin, AGP, Zig, and JBR versions. The synchronizer updates all managed build files, scripts, documentation, and CI fallbacks in one operation:

```bash
python3 scripts/sync_version.py --set wasmtime_version=47.0.2
python3 scripts/sync_version.py --check
python3 scripts/test_sync_versions.py
```

`sync_versions.py` remains available for existing automation. Both entry points use the same implementation and manifest.

## Kotlin Documentation Style

Kotlin declarations in runtime and test sources use KDoc (`/** ... */`) for API and test intent. Keep comments required by external test formats, such as `// WITH_STDLIB`, unchanged. Prefer a focused KDoc on the class or test function over narration inside the assertion body.
