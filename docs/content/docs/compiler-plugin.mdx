# Compiler Plugin

## IR Transformation Pipeline

The `wasmline-kotlin-plugin` runs during the **Kotlin IR compilation phase**. It does not use KSP and does not generate source files. The selected guest transport determines the final export or initialization hook.

| Step | Class | Operation |
|---|---|---|
| 1 — Discovery | `WasmlineIrGenerationExtension` | Traverses all `IrDeclarationContainer` nodes; collects `IrClass` declarations with `WasmlineService` in the supertype hierarchy |
| 2 — Validation | `WasmlineServiceContractValidator` | Validates each contract and reports compiler errors for unsupported declarations |
| 3 — Bridge synthesis | `WasmlineBridgeGenerator` | Synthesizes one `internal class {Contract}_WasmlineBridge : WasmlineGeneratedBridge` per validated contract; injects the class directly into the parent `IrFile` |
| 4 — Call-site rewriting | `WasmlineTypedEntryPointRewriter` | Locates all `link<T>()`, `bind(contract, impl)`, and `bind(impl)` call sites; replaces each with a direct bridge instantiation expression |
| 5 — Guest transport hook | `WasmlineWasiEntryExportGenerator` or `WasmlineComponentServiceInitGenerator` | Generates Core WASI exports or wires the Component Service initialization hook, according to compiler options |

## Static Contract Constraints

The following constraints are enforced at compile time. Any violation is reported as a **compiler error** and prevents successful IR generation:

| Constraint | Requirement |
|---|---|
| Declaration kind | A contract must be an `interface` that directly or indirectly extends `WasmlineService` |
| Properties | Service properties are not supported; declare functions instead |
| Member visibility | All functions must be declared `public` |
| Suspendability | `suspend` modifier is not permitted on any contract function |
| Generic type parameters | Not permitted on the contract or its functions |
| Method name uniqueness | Overloaded method names within a single contract are not supported |
| `vararg` parameters | Not permitted |
| Default parameter values | Not permitted |
| Extension receivers | Extension functions and properties are not supported as contract members |
| Service-typed values | Service contracts cannot be used as parameter or return types |

Functions may have multiple regular parameters. The generated bridge builds a serializer array and parameter descriptor for the full parameter list.

## Action Identifier

Each service method uses this action string:

```text
com.example.EchoService#echo
```

The generated caller, binder, and dispatcher use the same value. Overloaded method names are prohibited so the contract name and method name remain sufficient. Changing the contract package, contract name, or method name changes the action. Changing parameter types keeps the action but changes the serialized payload contract and must be treated as a compatibility change.

## IR Box Test Workflow

Box test fixtures reside in `wasmline-kotlin-plugin/testData/box/`. Each fixture consists of a source file with a `fun box(): String` entry point returning `"OK"` on successful execution:

```bash
cd wasmline-multiplatform

# 1. Author or modify a fixture in testData/box/{name}.kt
# 2. Regenerate the test runner
./gradlew :wasmline-kotlin-plugin:generateTests

# 3. Execute — FIR and IR snapshots are generated on the first run
./gradlew :wasmline-kotlin-plugin:test \
  --tests 'crow.wasmline.kotlin.runners.JvmBoxTestGenerated'

# 4. Review generated *.fir.txt and *.fir.ir.txt before committing
```

<Callout type="warn" title="Auto-generated build artifacts">
  The following files are **auto-generated build artifacts** and must never be edited manually: `test-gen/**`, `testData/box/*.fir.txt`, and `testData/box/*.fir.ir.txt`. Manual edits are overwritten or rejected by the next generation and test pass.
</Callout>

cd wasmline-multiplatform

./gradlew :wasmline-kotlin-plugin:generateTests
