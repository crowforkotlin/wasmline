## 执行栈

Wasmline 从 `commonMain` / `hostMain` 暴露统一 API，并按目标平台选择执行路径：原生目标（Android、iOS、macOS、Linux、Windows）经 `wasmline-core`（C/C++，Zig 0.16.0 编译）调用 wasmtime C-API 执行插件；Web 目标（Kotlin/JS、Kotlin/WasmJS）经内联 JS 运行时调用浏览器原生 WebAssembly API 执行插件，不经过 wasmtime。

### 原生目标栈 — Android · iOS · macOS · Linux · Windows

```text
Host Application  (commonMain / hostMain)
        │
        │  module.link<T>()      — IR-synthesized typed outbound proxy
        │  module.bind(impl)     — IR-synthesized inbound dispatch registration
        │
        ▼
Platform actual  (jniMain / iosMain)
        │  JNI external declarations          — Android, macOS, Linux, Windows
        │  Kotlin/Native C Interop (.def)     — iOS
        ▼
wasmline-core  (C/C++ · Zig 0.16.0)
        │  Engine.cpp               — Wasmtime engine 生命周期与 backend 选择
        │  Module.cpp/Component.cpp — 仅反序列化 Core 与 Component 产物的缓存
        │  Session variants         — Wasmline Service、Raw Export 与 Component 调用
        │  Api.cpp                  — JNI / C Interop surface (load, invoke, setOutbound, release)
        ▼
wasmtime C-API  v47.0.2
        │  Sandboxed execution; hardware-accelerated AOT; per-session memory isolation
        ▼
Precompiled artifact  (.cwasm — Cranelift 原生 AOT  |  .pwasm — Pulley 字节码；Core 或 Component 需独立声明)
```

产物层与引擎层是两组独立能力。Cranelift Wasmtime 构建同时包含 Cranelift 编译器和 Pulley 解释器，因此可以加载匹配的 `.cwasm`，并在缺少时回退到 `.pwasm`。Pulley 引擎构建只包含 Pulley 解释器，仅接受 `.pwasm`。iOS 使用 Pulley 引擎，因此始终选择 `.pwasm`。

### Web 目标栈 — Kotlin/JS · Kotlin/WasmJS

```text
Host Application  (commonMain / hostMain)
        │
        │  module.link<T>()      — IR-synthesized proxy (same IR pipeline as native)
        │  module.bind(impl)     — dispatch registration (same IR pipeline as native)
        │
        ▼
webMain / jsMain / wasmJsMain
        │  WasmlineWeb · WebWasmArtifacts · WebWasmPlugin
        ▼
Inline JS runtime  (Kotlin js() interop — no external .js files emitted)
        │
        ▼
Browser WebAssembly API  (WebAssembly.Module + WebAssembly.Instance)
        │
        ├── Import namespace: wasi_snapshot_preview1
        │     fd_write         — UTF-8 stdout/stderr 经 WasmlineLog 或 println 输出
        │     random_get       — Kotlin Random.nextBytes
        │     clock_time_get   — 将 Date.now() 的毫秒值转换为纳秒值
        │
        └── Import namespace: env  (Wasmline bridge protocol)
              bridge_inbound_copy_params     — write action + payload into Wasm linear memory
              bridge_inbound_set_response    — extract response bytes from Wasm linear memory
              bridge_outbound_call_host      — synchronous plugin-to-host dispatch callback
              bridge_outbound_get_response   — copy oversized outbound response to caller buffer
        │
        ▼
Plugin binary  (raw .wasm — 先通过 Fetch 异步预取，再从字节缓存同步加载)
```

## 执行模型

运行时根据 `WasmlineArtifactDescriptor` 选择后端。文件扩展名不用于选择执行模型。

| 执行模型 | 调用协议 | 运行时边界 | Core 响应帧 |
|---|---|---|---|
| `CORE_WASM` | `WASMLINE_SERVICE` | `Session`、action 路由和线性内存 | 使用 |
| `CORE_WASM` | `RAW_EXPORT` | `RawModuleSession` 和已声明的 Core 数值 ABI | 不使用 |
| `COMPONENT_MODEL` | `WASMLINE_SERVICE` | `ComponentSession` 和固定 `wasmline.wit` envelope | 不使用 |
| `COMPONENT_MODEL` | `COMPONENT_EXPORT` | `ComponentSession` 和 Component Model 值 | 不使用 |

`WASMLINE_SERVICE` 选择 Wasmline 服务 API。与 `CORE_WASM` 组合时，响应字节使用固定的 `WLMF` magic 标记和一个字节的 `frameVersion`，当前值为 `1`；与 `COMPONENT_MODEL` 组合时，则使用固定的 `wasmline:service@1.0.0` WIT envelope 和 Canonical ABI。因此真正决定 transport 的是执行模型，不能只看协议名。

Raw Export 使用显式声明的数值 ABI。当前公共 raw 值包括 `i32`、`i64`、`f32` 和 `f64`。该路径不分配或解析 Core 响应帧。

Component Model 调用通过 Wasmtime Component Model API 反序列化预编译的 Component `.cwasm` 或 `.pwasm` 产物。该路径使用 Component Model typed value，不要求 Core 线性内存、`__wasmline_wasi_entry` 或 Core 响应帧。运行时 loader 不会执行 `wit-bindgen`、`wasm-tools` 或 `wasmtime compile`；可选的 `wasmline-plugin-core`、Gradle 插件与 CLI 构建流水线会在加载前完成这些步骤。`contractMetadata` 用于记录调用契约、执行校验和生成文档，不是编译器输入。

三种路径共享相同的结果语义。未绑定 action 返回失败结果 `ACTION_NOT_BOUND`，不表示为空的成功 payload，也不要求抛出异常。Core 路径通过响应帧传递该结果；Raw Export 和 Component Model 通过 typed result carrier 传递该结果。违反编程契约、运行时状态不可恢复，或无法构造可靠结果时，才使用异常。

当前浏览器实现仅支持 Core Wasmline bridge。Raw Export 和 Component Model typed 调用通过 native 后端执行，因为它们需要 Wasmtime C API。这是目标平台的能力边界，不改变产物模型。

## 模块依赖关系图

```text
wasmline-cli ───────────► wasmline-plugin-core ───────► wasmline-loader ──► wasmline
wasmline-gradle-plugin ─► wasmline-plugin-core
        │
        └───────────────► wasmline-kotlin-plugin  (编译期 IR 变换)

wasmline ◄──── native runtime assets ──── wasmline-engine-cranelift / wasmline-engine-pulley
wasmline-network-ktor / wasmline-network-okhttp ──────► wasmline-loader
wasmline-core (C/C++) ◄──── JNI / C Interop ────────── wasmline
```

network、cache、trusted key 与 load request API 都归 `wasmline-loader` 所有。Ktor 与 OkHttp 构件实现 loader 的 suspend network SPI，并单向依赖 loader；核心 `wasmline` runtime 不依赖任何 HTTP engine。应用只在远程缓存未命中时选择 adapter：Ktor 覆盖 JVM、Android 与 iOS，OkHttp 覆盖 JVM 与 Android。浏览器 raw `.wasm` 仍使用独立的 `WasmlineWeb.prefetch()` 流程。

## 仓库目录结构

```text
wasmline/
├── wasmline-core/                      # C/C++ wasmtime bridge (Engine, Module, Session, Api)
├── wasmline-multiplatform/
│   ├── wasmline/                       # Core Kotlin runtime — execution, dispatch, serialization SPI
│   │   ├── commonMain/                 # Platform-agnostic contracts and bridge abstractions
│   │   ├── hostMain/                   # Host API: Wasmline, WasmlineLoadState, link<T>(), bind()
│   │   ├── jniMain/                    # JVM / Android actual — JNI external declarations
│   │   ├── iosMain/                    # iOS actual — Kotlin/Native C Interop
│   │   ├── webMain/                    # 共享 Web host runtime 与 expect binding contract
│   │   ├── jsMain/                     # Kotlin/JS binding actual
│   │   ├── wasmJsMain/                 # Kotlin/WasmJS binding actual
│   │   └── wasmWasiMain/               # Core 与 Component Service guest hook
│   ├── wasmline-loader/                # Load request/options、cache/network SPI 与 .wlm 校验
│   ├── wasmline-plugin-core/           # 共享 Core/Component 构建、签名、打包与工具链逻辑
│   ├── wasmline-cli/                   # plugin-core 与 loader 操作的 CLI adapter
│   ├── wasmline-android/               # Android native bindings (CMake / JNI C++)
│   ├── wasmline-kotlin-plugin/         # Kotlin IR compiler plugin — bridge synthesis, call-site rewriting
│   ├── wasmline-gradle-plugin/         # 基于 compiler plugin 与 plugin-core 的消费端 DSL 和任务
│   ├── wasmline-engine-cranelift/      # Cranelift runtime distribution 与平台变体
│   ├── wasmline-engine-pulley/         # Pulley runtime distribution 与平台变体
│   ├── wasmline-network-ktor/          # Ktor loader 网络 adapter
│   ├── wasmline-network-okhttp/        # OkHttp loader 网络 adapter
│   ├── wasmline-plugin-test/           # 端到端 plugin 与 native 集成测试
│   └── wasmline-build-logic/           # Shared Gradle convention plugins
├── wasmline-samples/
│   ├── kotlin/                         # Kotlin plugin、Component fixture 与 host app
│   ├── rust/                           # Rust Component fixture
│   ├── c/                              # C Component fixture
│   └── cpp/                            # C++ Component fixture
├── scripts/                            # 环境、资产、lint 与版本同步
├── build/                              # Root build outputs, including build/platforms/ wasmtime min C-API assets
└── docs/                               # Documentation site (Next.js + Fumadocs)
```
