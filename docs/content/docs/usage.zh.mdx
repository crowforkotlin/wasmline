# 使用指南

以下示例展示完整的集成流程：定义服务契约、在插件中实现契约、在宿主中加载插件并调用其服务。

## 定义服务契约

服务契约是在共享源码（`commonMain`）中声明并继承 `WasmlineService` 的 Kotlin `interface`。该契约定义宿主与插件之间的二进制协议边界。每个方法使用 `<完全限定契约名>#<方法名>` 形式的 action；不支持同名重载方法。

```kotlin
// shared/src/commonMain/kotlin/com/example/EchoService.kt
import crow.wasmline.WasmlineService

interface EchoService : WasmlineService {
    fun echo(message: String): String
}
```

## 实现插件（WASI 目标）

插件二进制通过 `Wasmline.current.bind(impl)` 注册服务实现。IR 编译器插件会在 IR 层将该调用点重写为把实现注册到生成的 `*_WasmlineBridge` 中：

```kotlin
// plugin/src/wasmWasiMain/kotlin/Main.kt
import crow.wasmline.Wasmline
import crow.wasmline.bind

val wasmline = Wasmline.current

fun main() {
    wasmline.bind(object : EchoService {
        override fun echo(message: String): String {
            return "Response from WASI plugin: $message"
        }
    })
}
```

## 宿主端模块加载与服务调用

宿主通过 suspend API `WasmlineLoader.load()` 加载插件。原生目标使用已验证的 manifest 或预编译 `.pwasm` / `.cwasm` 产物；raw `.wasm` 仅适用于浏览器的 Core Wasmline 路径。`http(s)://` source 按远程 manifest 解析并完成校验后再加载产物。加载后通过 `bind(impl)` 注册插件可访问的宿主侧服务实现，并通过 `link<T>()` 获取插件侧服务的类型安全代理：

```kotlin
import crow.wasmline.WasmlineConfig
import crow.wasmline.WasmlineLoadResult
import crow.wasmline.bind
import crow.wasmline.link
import crow.wasmline.loader.WasmlineLoader
import crow.wasmline.loader.WasmlineLoadOptions
import crow.wasmline.loader.WasmlineTrustedKeySet
import crow.wasmline.network.ktor.KtorNetworkClient

suspend fun main() {
    val module = when (val result = WasmlineLoader.load(
        source = "https://example.com/plugin/manifest.wlm",
        options = WasmlineLoadOptions(
            runtimeConfig = WasmlineConfig(),
            networkClient = KtorNetworkClient(),
            trustedKeys = WasmlineTrustedKeySet.Builder()
                .addHex(
                    algorithm = "Ed25519",
                    keyId = "release",
                    publicKeyHex = "5a778289bee0c57b05a1c48c8ef312da6ce8e4e4f13fc1a2e8e5aa4cde7ae0db",
                )
                .build(),
        ),
    )) {
        is WasmlineLoadResult.Success -> result.wasmline
        is WasmlineLoadResult.Failure -> error(result.failure.message)
    }

    module.bind(object : HostNotificationService {
        override fun notify(event: String) { /* host-side handler */ }
    })

    val response = module.link<EchoService>().echo("ping")
    module.close()
}
```

本地产物和本地 manifest 不需要 network 构件。加载远程 manifest 时，可选择 `wasmline-network-ktor`（JVM、Android、iOS）或 `wasmline-network-okhttp`（JVM、Android）。只有 fresh manifest 或 artifact 未命中缓存时才会调用 adapter；manifest 与所选 artifact 均已缓存时，即使没有 network client 也能继续加载。内置文件缓存会把 artifact body 流式写入原子发布的内容寻址文件，并在超过 `WasmlineLoadOptions.maxCacheBytes` 时淘汰旧条目；默认上限为 512 MiB。应用也可以自行实现 `WasmlineNetworkClient`、提供自定义缓存，或提供自定义远程 resolver。

一个远程 manifest 可以包含多个 Wasmtime AOT profile 和平台 variant。Loader
先校验 Ed25519 envelope，再把 manifest 与 native engine 实际报告的 backend-specific
profile ID 和 target identity 比较，最后只请求一个内容寻址 artifact。冷加载通常
只有一次 manifest 请求和一次 artifact 请求，不会下载完整离线 ZIP 或无关 variant。
Core Web package 只选择一个与 profile 无关的 RAW_WASM variant。

## 运行时生命周期与 API 职责

`WasmlineLoader`、`WasmlineRuntime` 与已加载的 `Wasmline` 各自承担不同职责：

| API | 职责 |
|---|---|
| `WasmlineLoader` | 解析来源、校验 package、选择兼容产物并加载 |
| `WasmlineRuntime` | 管理进程级的平台链接、引擎预热、运行时信息与全局关闭 |
| `Wasmline` | 表示一个已加载产物，并通过 `close()` 释放该句柄 |

大多数应用应直接调用 `WasmlineLoader.load()`；原生链接与引擎创建会惰性完成。启动优化是可选操作：

```kotlin
import crow.wasmline.WasmlineEngineKind
import crow.wasmline.WasmlineRuntime

WasmlineRuntime.preload() // 只链接平台运行时，不创建引擎。
WasmlineRuntime.warmUp(WasmlineEngineKind.PULLEY) // 提前创建指定引擎。
```

`WasmlineRuntime.nativeInfo()` 返回已链接原生运行时的身份信息及其 `supportedEngines`；浏览器中返回 `null`，也不提供原生引擎预热。对当前引擎重复调用 `warmUp()` 是安全的。只有所有已加载产物句柄都关闭后才能切换引擎；否则预热或冲突产物加载会失败，但不会使现有句柄失效。

正常的产物所有权应使用 `Wasmline.close()`。`WasmlineRuntime.shutdown()` 会释放全部引擎、产物与 session，并使所有存活的 `Wasmline` 句柄失效，因此只应在进程或应用退出时使用。

需要传递 metadata 或自定义 resolver 时，可直接使用公开的完整 request overload：

```kotlin
import crow.wasmline.WasmlineLoadResult
import crow.wasmline.loader.WasmlineLoadRequest
import crow.wasmline.loader.WasmlineLoadOptions
import crow.wasmline.loader.WasmlineLoader
import crow.wasmline.loader.WasmlineRemotePackageResolver
import crow.wasmline.loader.WasmlineSource
import crow.wasmline.loader.WasmlineSourceResolvers

suspend fun loadWithCustomResolver(
    packageUrl: String,
    loadOptions: WasmlineLoadOptions,
    appPackageResolver: WasmlineRemotePackageResolver,
): WasmlineLoadResult =
    WasmlineLoader.load(
        WasmlineLoadRequest(
            source = WasmlineSource.RemoteManifestUrl(packageUrl),
            options = loadOptions,
            metadata = mapOf("channel" to "beta"),
            resolvers = WasmlineSourceResolvers(remotePackage = appPackageResolver),
        ),
    )
```

<Callout type="info" title="IR 插件重写目标">
  `link<T>()` 与 `bind(impl)` 是 Kotlin IR 编译器插件的重写目标。IR 插件会将每个调用点替换为对生成的 `*_WasmlineBridge` 的直接调用。如果编译单元未应用 `wasmline-kotlin-plugin`，这些函数会在运行时抛出 `UnsupportedOperationException`。
</Callout>

## 选择调用路径

当产物不是默认的 Core Wasmline 模块时，使用 `WasmlineArtifactDescriptor`。执行模型与调用协议必须成对声明，加载器会验证二者的组合：

```kotlin
import crow.wasmline.WasmlineArtifactDescriptor
import crow.wasmline.WasmlineArtifactFormat
import crow.wasmline.WasmlineComponentValue
import crow.wasmline.WasmlineEngineKind
import crow.wasmline.WasmlineExecutionModel
import crow.wasmline.WasmlineInvocationProtocol
import crow.wasmline.WasmlineLoadResult
import crow.wasmline.WasmlineRuntime
import crow.wasmline.invokeComponentResult
import crow.wasmline.invocation.WasmlineCallResult
import crow.wasmline.loader.WasmlineLoader

val runtime = requireNotNull(WasmlineRuntime.nativeInfo())
val pulleyProfileId = requireNotNull(
    runtime.aotCompatibilityProfileIdsByBackend[WasmlineEngineKind.PULLEY],
).single()
val result = WasmlineLoader.load(
    WasmlineArtifactDescriptor(
        path = "component.pwasm",
        artifactFormat = WasmlineArtifactFormat.PWASM,
        architecture = "pulley${runtime.pointerWidth}",
        pointerWidth = runtime.pointerWidth,
        aotCompatibilityProfileId = pulleyProfileId,
        executionModel = WasmlineExecutionModel.COMPONENT_MODEL,
        invocationProtocol = WasmlineInvocationProtocol.COMPONENT_EXPORT,
        exportName = "wasmline:sample-component-export/calculator@1.0.0#add",
        contractMetadata = mapOf("params" to "s32,s32", "result" to "s32"),
    ),
)

when (result) {
    is WasmlineLoadResult.Success -> when (
        val call = result.wasmline.invokeComponentResult(
            exportName = "add",
            arguments = listOf(WasmlineComponentValue.S32(1), WasmlineComponentValue.S32(2)),
        ),
    ) {
        is WasmlineCallResult.Success -> useValues(call.value.values)
        is WasmlineCallResult.Failure -> log(call.failure.message)
    }

        is WasmlineLoadResult.Failure -> log(result.failure.message)
}
```

这种显式 descriptor 用于已知的本地 artifact。加载 package manifest 时，只需传入
路径或 URL，由共享 selector 选择 CWASM、PWASM 或 Web WASM。不要根据
`wasmtimeVersion` 推导 AOT profile。

`WASMLINE_SERVICE` 是服务协议。`CORE_WASM` 可以使用 Service bridge，也可以使用
`RAW_EXPORT`。Raw Export 通过 `CoreWasmModule` 和 `CoreWasmSession` 使用 `RawValue`
（`i32`、`i64`、`f32`、`f64`）、多返回值、同步 `RawImport` 回调与有边界检查的
`RawMemory`，不使用 action/payload 帧。Web 端在加载前通过 `WasmlineWeb.registerBytes()`
注册字节，或先完成 prefetch，并在 `instantiate()` 前注册所有 imports；JavaScript 边界的
`i64` 使用 `BigInt`，import 不能等待异步 API。native Raw Export 通过 Wasmtime 加载匹配的
`.cwasm` 或 `.pwasm`。Component Model 仍是独立的 typed WIT 边界。运行时不会在加载过程中执行
WIT-to-Wasm 或 binding 工具；可选的 Gradle/CLI Component 流水线会提前完成这些构建步骤。
Service envelope 与回调流程参见 [Wasmline Service 指南](/zh/docs/component-service)。

对于直接 Core Wasm 模块，应把加载和实例化分开，以便在创建
WebAssembly instance 前注册全部宿主 import：

```kotlin
import crow.wasmline.CoreWasmSessionOptions
import crow.wasmline.RawAbiMetadata
import crow.wasmline.RawExport
import crow.wasmline.RawExportKind
import crow.wasmline.WasmlineArtifactDescriptor
import crow.wasmline.WasmlineArtifactFormat
import crow.wasmline.RawFunctionSignature
import crow.wasmline.RawImport
import crow.wasmline.RawImportDeclaration
import crow.wasmline.RawValue
import crow.wasmline.RawValueType
import crow.wasmline.WasmlineCoreLoadResult
import crow.wasmline.WasmlineExecutionModel
import crow.wasmline.WasmlineInvocationProtocol
import crow.wasmline.WasmlineWeb
import crow.wasmline.invocation.WasmlineCallResult
import crow.wasmline.loader.WasmlineLoader

WasmlineWeb.registerBytes("math.wasm", wasmBytes)
val module = when (val loaded = WasmlineLoader.loadCoreModule(
    WasmlineArtifactDescriptor(
        path = "math.wasm",
        artifactFormat = WasmlineArtifactFormat.RAW_WASM,
        executionModel = WasmlineExecutionModel.CORE_WASM,
        invocationProtocol = WasmlineInvocationProtocol.RAW_EXPORT,
        rawAbi = RawAbiMetadata(
            exports = listOf(
                RawExport(
                    name = "add",
                    kind = RawExportKind.FUNCTION,
                    signature = RawFunctionSignature(
                        parameters = listOf(RawValueType.I32, RawValueType.I32),
                        results = listOf(RawValueType.I32),
                    ),
                ),
            ),
            imports = listOf(
                RawImportDeclaration(
                    module = "env",
                    name = "host_add",
                    signature = RawFunctionSignature(
                        parameters = listOf(RawValueType.I32, RawValueType.I32),
                        results = listOf(RawValueType.I32),
                    ),
                ),
            ),
        ),
    ),
)) {
    is WasmlineCoreLoadResult.Success -> loaded.module
    is WasmlineCoreLoadResult.Failure -> error("${loaded.failure.code}: ${loaded.failure.message}")
}

val session = module.instantiate(
    CoreWasmSessionOptions(
        imports = listOf(
            RawImport(
                module = "env",
                name = "host_add",
                signature = RawFunctionSignature(
                    parameters = listOf(RawValueType.I32, RawValueType.I32),
                    results = listOf(RawValueType.I32),
                ),
            ) { _, values ->
                WasmlineCallResult.Success(
                    listOf(RawValue.I32((values[0] as RawValue.I32).value + (values[1] as RawValue.I32).value)),
                )
            },
        ),
    ),
).getOrThrow()

val values = session.invoke("add", listOf(RawValue.I32(2), RawValue.I32(3))).getOrThrow()
session.memory?.write(0, byteArrayOf(1, 2, 3))?.getOrThrow()
session.close()
module.close()
```

规范错误类型分为：结果值中的 `WasmlineFailure`、显式抛出适配器使用的
`WasmlineException`，以及模块尚未创建时的 `WasmlineLoadFailure`。
结果 API 只通过 `failure`、`failure.code` 和 `failure.message` 表达失败。

## 结果与异常边界

当普通调用错误需要作为数据处理时，使用 `callResult`、`invokeRawResult` 和 Core session API。
结果只有 `Success(value)` 或 `Failure(failure)` 两种状态；分支判断应使用 `failure.code`，不应解析错误消息。

没有绑定 handler 的 action 返回 `ACTION_NOT_BOUND`。它不表示为空 payload，也不会导致宿主崩溃。未知 action、无效 payload、handler 失败、trap、传输失败和响应帧格式错误，在运行时能够构造结果时都返回失败结果。

`getOrNull()` 与 `failureOrNull()` 用于无异常读取。`throwOnFailure()` 只在明确需要时将
`WasmlineFailure` 适配为 `WasmlineException`，不属于默认结果路径。

Core 响应帧使用固定的 `WLMF` magic 标记和一个字节的 `frameVersion`，当前值为 `1`。magic 用于识别帧格式，不提供身份认证。`frameVersion` 表示响应字节布局，不表示 Wasmtime、Kotlin、框架或业务 API 版本。Raw Export 和 Component Model 调用不会增加该 Core 响应帧。

## 稳定错误码

错误码是稳定标识符。应用程序应根据错误码分支，错误消息只用于诊断。

| 错误码 | 数值 | 含义 |
|---|---:|---|
| `ACTION_NOT_BOUND` | `1001` | 当前 action 作用域没有绑定 handler。 |
| `UNKNOWN_ACTION` | `1002` | action 名称未注册。 |
| `INVALID_PAYLOAD` | `1003` | payload 或 typed 参数无效。 |
| `HANDLER_FAILED` | `1004` | handler 执行失败。 |
| `SERIALIZATION_FAILED` | `1005` | 业务数据无法序列化。 |
| `ENGINE_NOT_INITIALIZED` | `2001` | Wasmtime engine 未初始化。 |
| `CORE_TRAP` | `2002` | Core Wasm 执行发生 trap。 |
| `CORE_EXPORT_NOT_FOUND` | `2003` | Core export 不存在。 |
| `INVOCATION_PROTOCOL_MISMATCH` | `2004` | 描述对象与调用 API 不匹配。 |
| `MODULE_FORMAT_INVALID` | `2201` | raw 或 AOT 模块格式无效。 |
| `WASM_FEATURE_UNSUPPORTED` | `2202` | 所需 WebAssembly feature 不可用。 |
| `IMPORT_MISSING` | `2203` | 声明的宿主 import 未注册。 |
| `IMPORT_SIGNATURE_MISMATCH` | `2204` | import 签名与模块不匹配。 |
| `INSTANTIATION_FAILED` | `2205` | 模块实例化失败。 |
| `EXPORT_KIND_MISMATCH` | `2206` | export 存在但种类不正确。 |
| `ARGUMENT_COUNT_MISMATCH` | `2207` | 参数数量不正确。 |
| `ARGUMENT_TYPE_MISMATCH` | `2208` | 参数类型不正确。 |
| `RESULT_TYPE_UNSUPPORTED` | `2209` | 返回类型不在标量 ABI 范围内。 |
| `MEMORY_OUT_OF_BOUNDS` | `2210` | 线性内存范围无效。 |
| `IMPORT_HANDLER_FAILED` | `2211` | 同步宿主 import 失败。 |
| `SESSION_CLOSED` | `2212` | 使用了已关闭的 module 或 session。 |
| `CONCURRENT_ACCESS` | `2213` | session 已有进行中的操作。 |
| `REENTRANT_CALL` | `2214` | import 回调重新进入同一 session。 |
| `UNSUPPORTED_EXPORT_KIND` | `2215` | backend 不支持请求的 export 类型。 |
| `WASM_TRAP` | `2216` | Core Wasm 执行发生 trap。 |
| `EXPORT_SIGNATURE_MISSING` | `2217` | Web 调用缺少签名 metadata。 |
| `EXPORT_NOT_FOUND` | `2218` | 请求的 raw export 不存在。 |
| `COMPONENT_TRAP` | `2101` | Component Model 执行发生 trap。 |
| `COMPONENT_EXPORT_NOT_FOUND` | `2102` | Component export 不存在。 |
| `COMPONENT_CALL_FAILED` | `2103` | Component 调用未成功返回。 |
| `RESPONSE_MALFORMED` | `3001` | 响应帧格式无效。 |
| `RESPONSE_MISSING` | `3002` | 没有返回响应。 |
| `TRANSPORT_FAILURE` | `3003` | 平台 bridge 失败。 |
| `RESPONSE_UNSUPPORTED_VERSION` | `3004` | Core 响应帧版本不受支持。 |

## 示例应用

参考实现位于 `wasmline-samples/kotlin/`：

| 模块 | 说明 |

| `sample-common` | 共享服务契约接口定义：`EchoService`、`TimeSyncService`、`WebBridgeService` |

| `sample-apps/multiplatform` | Compose Multiplatform 应用——Android 与 Desktop |
