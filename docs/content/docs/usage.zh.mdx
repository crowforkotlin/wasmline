# 使用指南

以下示例展示完整的集成流程：定义服务契约、在插件中实现契约、在宿主中加载插件并调用其服务。

## 定义服务契约

服务契约是在共享源码（`commonMain`）中声明并继承 `WasmlineService` 的 Kotlin `interface`。该契约定义宿主与插件之间的二进制协议边界。每个方法使用 `<完全限定契约名>#<方法名>` 形式的 action；不支持同名重载方法。

```kotlin
// shared/src/commonMain/kotlin/com/example/EchoService.kt
import crow.wasmline.WasmlineService

interface EchoService : WasmlineService {
    fun echo(message: String): String
}
```

## 实现插件（WASI 目标）

插件二进制通过 `Wasmline.current.bind(impl)` 注册服务实现。IR 编译器插件会在 IR 层将该调用点重写为把实现注册到生成的 `*_WasmlineBridge` 中：

```kotlin
// plugin/src/wasmWasiMain/kotlin/Main.kt
import crow.wasmline.Wasmline
import crow.wasmline.bind

val wasmline = Wasmline.current

fun main() {
    wasmline.bind(object : EchoService {
        override fun echo(message: String): String {
            return "Response from WASI plugin: $message"
        }
    })
}
```

## 宿主端模块加载与服务调用

宿主通过 suspend API `WasmlineLoader.load()` 加载插件。原生目标使用已验证的 manifest 或预编译 `.pwasm` / `.cwasm` 产物；raw `.wasm` 仅适用于浏览器的 Core Wasmline 路径。`http(s)://` source 按远程 manifest 解析并完成校验后再加载产物。加载后通过 `bind(impl)` 注册插件可访问的宿主侧服务实现，并通过 `link<T>()` 获取插件侧服务的类型安全代理：

```kotlin
import crow.wasmline.WasmlineConfig
import crow.wasmline.WasmlineLoadResult
import crow.wasmline.bind
import crow.wasmline.link
import crow.wasmline.loader.WasmlineLoader
import crow.wasmline.loader.WasmlineLoadOptions
import crow.wasmline.loader.WasmlineTrustedKeySet
import crow.wasmline.network.ktor.KtorNetworkClient

suspend fun main() {
    WasmlineLoader.bootstrap()

    val module = when (val result = WasmlineLoader.load(
        source = "https://example.com/plugin/manifest.wlm",
        options = WasmlineLoadOptions(
            runtimeConfig = WasmlineConfig(),
            networkClient = KtorNetworkClient(),
            trustedKeys = WasmlineTrustedKeySet.Builder()
                .addHex(
                    algorithm = "Ed25519",
                    keyId = "release",
                    publicKeyHex = "5a778289bee0c57b05a1c48c8ef312da6ce8e4e4f13fc1a2e8e5aa4cde7ae0db",
                )
                .build(),
        ),
    )) {
        is WasmlineLoadResult.Success -> result.wasmline
        is WasmlineLoadResult.Failure -> error(result.cause)
    }

    module.bind(object : HostNotificationService {
        override fun notify(event: String) { /* host-side handler */ }
    })

    val response = module.link<EchoService>().echo("ping")
    module.close()
}
```

本地产物和本地 manifest 不需要 network 构件。加载远程 manifest 时，可选择 `wasmline-network-ktor`（JVM、Android、iOS）或 `wasmline-network-okhttp`（JVM、Android）。只有 fresh manifest 或 artifact 未命中缓存时才会调用 adapter；manifest 与所选 artifact 均已缓存时，即使没有 network client 也能继续加载。应用也可以自行实现 `WasmlineNetworkClient`，或提供自定义远程 resolver。

需要传递 metadata 或自定义 resolver 时，可直接使用公开的完整 request overload：

```kotlin
import crow.wasmline.WasmlineLoadResult
import crow.wasmline.loader.WasmlineLoadRequest
import crow.wasmline.loader.WasmlineLoadOptions
import crow.wasmline.loader.WasmlineLoader
import crow.wasmline.loader.WasmlineRemotePackageResolver
import crow.wasmline.loader.WasmlineSource
import crow.wasmline.loader.WasmlineSourceResolvers

suspend fun loadWithCustomResolver(
    packageUrl: String,
    loadOptions: WasmlineLoadOptions,
    appPackageResolver: WasmlineRemotePackageResolver,
): WasmlineLoadResult =
    WasmlineLoader.load(
        WasmlineLoadRequest(
            source = WasmlineSource.RemoteManifestUrl(packageUrl),
            options = loadOptions,
            metadata = mapOf("channel" to "beta"),
            resolvers = WasmlineSourceResolvers(remotePackage = appPackageResolver),
        ),
    )
```

<Callout type="info" title="IR 插件重写目标">
  `link<T>()` 与 `bind(impl)` 是 Kotlin IR 编译器插件的重写目标。IR 插件会将每个调用点替换为对生成的 `*_WasmlineBridge` 的直接调用。如果编译单元未应用 `wasmline-kotlin-plugin`，这些函数会在运行时抛出 `UnsupportedOperationException`。
</Callout>

## 选择调用路径

当产物不是默认的 Core Wasmline 模块时，使用 `WasmlineArtifactDescriptor`。执行模型与调用协议必须成对声明，加载器会验证二者的组合：

```kotlin
import crow.wasmline.WasmlineArtifactDescriptor
import crow.wasmline.WasmlineArtifactFormat
import crow.wasmline.WasmlineComponentValue
import crow.wasmline.WasmlineExecutionModel
import crow.wasmline.WasmlineInvocationProtocol
import crow.wasmline.WasmlineLoadResult
import crow.wasmline.invokeComponentResult
import crow.wasmline.invocation.WasmlineCallResult
import crow.wasmline.loader.WasmlineLoader
import crow.wasmline.wasmlineNativeRuntimeInfo

val runtime = requireNotNull(wasmlineNativeRuntimeInfo())
val is64Bit = requireNotNull(runtime.is64Bit)
val result = WasmlineLoader.load(
    WasmlineArtifactDescriptor(
        path = "component.pwasm",
        artifactFormat = WasmlineArtifactFormat.PWASM,
        targetCpu = if (is64Bit) "pulley64" else "pulley32",
        targetCompilerVersion = "wasmtime-${runtime.wasmtimeVersion}",
        is64Bit = is64Bit,
        executionModel = WasmlineExecutionModel.COMPONENT_MODEL,
        invocationProtocol = WasmlineInvocationProtocol.COMPONENT_EXPORT,
        exportName = "wasmline:sample-component-export/calculator@1.0.0#add",
        contractMetadata = mapOf("params" to "s32,s32", "result" to "s32"),
    ),
)

when (result) {
    is WasmlineLoadResult.Success -> when (
        val call = result.wasmline.invokeComponentResult(
            exportName = "add",
            arguments = listOf(WasmlineComponentValue.S32(1), WasmlineComponentValue.S32(2)),
        ),
    ) {
        is WasmlineCallResult.Success -> useValues(call.value.values)
        is WasmlineCallResult.Failure -> log(call.error.message)
    }

    is WasmlineLoadResult.Failure -> log(result.cause)
}
```

`WASMLINE_SERVICE` 是统一的服务协议：`CORE_WASM` 使用既有 Core bridge，`COMPONENT_MODEL` 使用固定 `wasmline.wit` envelope。`CORE_WASM + RAW_EXPORT` 用于明确的数值 ABI，`COMPONENT_MODEL + COMPONENT_EXPORT` 用于业务专用 typed WIT value。运行时不会在加载过程中执行 WIT-to-Wasm 或 binding 工具；可选的 Gradle/CLI Component 流水线会提前完成这些构建步骤。Envelope 与回调流程参见 [Wasmline Service 指南](/zh/docs/component-service)。

## 结果与异常边界

当普通调用错误需要作为数据处理时，使用 `callResult`、`invokeRawResult` 和 `invokeComponentResult`。结果只有 `Success(value)` 或 `Failure(error)` 两种状态；分支判断应使用 `error.code`，不应解析错误消息。

没有绑定 handler 的 action 返回 `ACTION_NOT_BOUND`。它不表示为空 payload，也不会导致宿主崩溃。未知 action、无效 payload、handler 失败、trap、传输失败和响应帧格式错误，在运行时能够构造结果时都返回失败结果。

`getOrNull()` 与 `errorOrNull()` 用于无异常读取。`throwOnFailure()` 是为需要旧式异常调用方式的调用方提供的显式适配，不属于默认结果路径。违反编程契约、运行时对象状态无效，或无法可靠构造结果对象时，才适合使用异常。

Core 响应帧使用固定的 `WLMF` magic 标记和一个字节的 `frameVersion`，当前值为 `1`。magic 用于识别帧格式，不提供身份认证。`frameVersion` 表示响应字节布局，不表示 Wasmtime、Kotlin、框架或业务 API 版本。Raw Export 和 Component Model 调用不会增加该 Core 响应帧。

## 稳定错误码

错误码是稳定标识符。应用程序应根据错误码分支，错误消息只用于诊断。

| 错误码 | 数值 | 含义 |
|---|---:|---|
| `ACTION_NOT_BOUND` | `1001` | 当前 action 作用域没有绑定 handler。 |
| `UNKNOWN_ACTION` | `1002` | action 名称未注册。 |
| `INVALID_PAYLOAD` | `1003` | payload 或 typed 参数无效。 |
| `HANDLER_FAILED` | `1004` | handler 执行失败。 |
| `SERIALIZATION_FAILED` | `1005` | 业务数据无法序列化。 |
| `ENGINE_NOT_INITIALIZED` | `2001` | Wasmtime engine 未初始化。 |
| `CORE_TRAP` | `2002` | Core Wasm 执行发生 trap。 |
| `CORE_EXPORT_NOT_FOUND` | `2003` | Core export 不存在。 |
| `INVOCATION_PROTOCOL_MISMATCH` | `2004` | 描述对象与调用 API 不匹配。 |
| `COMPONENT_TRAP` | `2101` | Component Model 执行发生 trap。 |
| `COMPONENT_EXPORT_NOT_FOUND` | `2102` | Component export 不存在。 |
| `COMPONENT_CALL_FAILED` | `2103` | Component 调用未成功返回。 |
| `RESPONSE_MALFORMED` | `3001` | 响应帧格式无效。 |
| `RESPONSE_MISSING` | `3002` | 没有返回响应。 |
| `TRANSPORT_FAILURE` | `3003` | 平台 bridge 失败。 |
| `RESPONSE_UNSUPPORTED_VERSION` | `3004` | Core 响应帧版本不受支持。 |

## 示例应用

参考实现位于 `wasmline-samples/kotlin/`：

| 模块 | 说明 |
|---|---|
| `sample-common` | 共享服务契约接口定义：`EchoService`、`TimeSyncService`、`WebBridgeService` |
| `sample-plugin` | Kotlin/WasmWasi 插件——通过 `bind()` 注册实现，通过 `link()` 调用宿主服务 |
| `sample-component-plugin` | Kotlin/WasmWasi `wasmline:service@1.0.0` Component，包含生成的宿主回调 |
| `sample-apps/android` | Android 宿主——加载 `.pwasm` 产物，注册宿主回调，并调用插件服务 |
| `sample-apps/application` | JVM 无界面桌面宿主 |
| `sample-apps/multiplatform` | Compose Multiplatform 应用——Android 与 Desktop |
| `sample-apps/multiplatform/webApp` | Web 宿主——Kotlin/JS 与 Kotlin/WasmJS 目标 |
