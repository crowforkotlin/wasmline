# 测试

Wasmline 按边界拆分测试。每个会话仅执行一次仓库预检，执行时机是修改 Wasmline 文件后首次进行必要验证之前。没有需要验证的 Wasmline 文件修改时无需执行：

```bash
./scripts/wasmline doctor
```

## 测试矩阵

| 范围 | 模块 | 主要覆盖 | 命令 |
|---|---|---|---|
| Common runtime | `wasmline` | 响应帧、descriptor 与序列化 | `./gradlew :wasmline:jvmTest` |
| Host runtime | `wasmline` | 本地 artifact bridge、typed raw/component 调用与宿主 API 编译 | `./gradlew :wasmline:jvmTest` |
| Native Wasmtime | `wasmline` | JNI 生命周期、产物加载、raw export、component export | `./gradlew :wasmline:nativeAotJvmTest` |
| Kotlin/JS | `wasmline` | WebAssembly imports、值、内存与 exports | `./gradlew :wasmline:jsBrowserTest` |
| Kotlin/WasmJS | `wasmline` | WebAssembly imports、值、内存与 exports | `./gradlew :wasmline:wasmJsBrowserTest` |
| Kotlin/WasmWasi | `wasmline` | WASI 运行时集成 | `./gradlew :wasmline:wasmWasiNodeTest` |
| Loader | `wasmline-loader` | manifest、签名、本地与远程包解析 | `./gradlew :wasmline-loader:jvmTest` |
| CLI | `wasmline-cli` | 平台检测与密钥生成 | `./gradlew :wasmline-cli:test` |
| IR box | `wasmline-kotlin-plugin` | 生成 bridge 行为、编译器校验与 FIR/IR snapshot | 参见[编译器插件](/zh/docs/compiler-plugin) |

在 `wasmline-multiplatform/` 下运行主要 JVM 检查：

```bash
./gradlew :wasmline:jvmTest \
  :wasmline-loader:jvmTest \
  :wasmline-cli:test \
  :wasmline-kotlin-plugin:generateTests \
  :wasmline-kotlin-plugin:test
```

Native Wasmtime 测试从 `wasmline-engine-cranelift/src/jvmMain/resources/jni/` 加载 Cranelift JNI 库。普通 `jvmTest` 会排除需要序列化 AOT 产物的测试。`nativeAotJvmTest` 先运行 `:wasmline-native-test-fixtures:assembleNativeTestFixtures`，把 fixture index 传给测试进程，再运行全部 native AOT 集成测试。fixture 缺失、文件被修改或 index 内容不正确都会使任务失败。

## Native AOT Fixture

Fixture 源文件提交在 `wasmline-native-test-fixtures/src/fixtures/`。该模块把 `.cwasm` 或 `.pwasm` 写入自己的 `build/` 目录；这些二进制文件不能提交到仓库，也不能通过测试环境变量手工提供。

从仓库根目录开始时，Linux JVM 校验前必须先构建 Cranelift JNI 库。fixture 任务会生成宿主平台的 Cranelift target 和可移植的 `pulley64` target：

```bash
./scripts/wasmline jni build --engine cranelift
cd wasmline-multiplatform
rustup target add wasm32-wasip2
./gradlew :wasmline:nativeAotJvmTest \
  -Pwasmline.native.fixtures.targets=x86_64-linux,pulley64 \
  --no-daemon
```

fixture index 记录 fixture ID、执行模型、调用协议、产物格式和后端、请求与规范化目标、AOT profile ID、相对路径、文件大小和 SHA-256 摘要。JVM suite 会通过 Cranelift native library 加载 `raw-export-basic` 的 `pulley64` PWASM fixture，并调用其 `add` export。测试 helper 只选择与当前 native runtime 的 target 和 profile 匹配的条目，并在复制到临时文件前再次校验文件。

iOS simulator 只使用可移植 Pulley 目标。请在 macOS 上从仓库根目录运行：

```bash
./scripts/wasmline wasmtime download --target ios-simulator-arm64 --engine pulley
cd wasmline-multiplatform
rustup target add wasm32-wasip2
./gradlew :wasmline:iosSimulatorArm64Test \
  :wasmline-loader:iosSimulatorArm64Test \
  -Pwasmline.native.fixtures.targets=pulley64 \
  --no-daemon
```

当 index 缺失、选中的 fixture 与请求的执行模型、调用协议、Pulley 后端、`pulley64` 目标、`.pwasm` 后缀、文件大小或已链接的 AOT profile 不一致时，iOS 测试会失败。Rust resource fixture 生成前必须安装 `wasm32-wasip2` target。

## IR 测试规则

当前启用的 IR 夹具位于 `wasmline-kotlin-plugin/testData/box/`：

- `box/*.kt` 通过 `fun box(): String` 校验生成的 bridge 行为。
- `test-gen/` 与 FIR/IR snapshot 属于生成产物。

只编辑源夹具，然后用以下命令重新生成 runner 和 snapshot：

```bash
./gradlew :wasmline-kotlin-plugin:generateTests
./gradlew :wasmline-kotlin-plugin:test \
  --tests 'crow.wasmline.kotlin.runners.JvmBoxTestGenerated'
```

不要手动编辑 `test-gen/`、`*.fir.txt` 或 `*.fir.ir.txt`。

仓库保留了 `AbstractJvmDiagnosticTest` 框架，但生成器中的 diagnostics model 尚未启用。当前没有 `testData/diagnostics/` 目录或 `JvmDiagnosticsTestGenerated` runner。

## 版本校验

`versions.json` 是项目、sample-plugin、Wasmtime、Kotlin、ktlint、Dokka、AGP、Zig 与 JBR 版本的唯一源。同步器会一次更新所有受管理的构建文件、脚本、文档与 CI fallback：

```bash
./scripts/wasmline versions sync
./scripts/wasmline versions sync \
  --set wasmtime_version=48.0.1 \
  --set wasmtime_release_version=48.0.1.1
./scripts/wasmline versions check
python3 scripts/tests/test_versions.py

# 查询或更新固定的独立 Kotlin 格式化器版本。
./scripts/wasmline versions check-ktlint
./scripts/wasmline versions update-ktlint
```

手动修改 `versions.json` 后执行 `versions sync`，或者使用 `--set` 在一次命令中更新 manifest 并完成同步。本地 Kotlin lint 与 CI 都解析固定的 `ktlint_version`，不会自动漂移到未经审阅的 release。每周运行的 `Update ktlint` workflow 在发现新的稳定版时会创建或更新一个 PR。测试命令仅运行独立的回归测试，不会修改版本。

## Kotlin 注释规范

runtime 与 test 源码中的 Kotlin 声明使用 KDoc（`/** ... */`）说明 API 与测试意图。外部测试格式要求的注释，例如 `// WITH_STDLIB`，必须保留。相比在断言体内逐行叙述，更推荐在类或测试函数上写简洁的 KDoc。
