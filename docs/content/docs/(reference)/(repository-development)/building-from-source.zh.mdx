# 从源码编译

本页面面向需要构建或修改 Wasmline 仓库的贡献者。如果只是在应用中使用
Wasmline，请参阅[安装](/zh/docs/installation)。

## 所需工具

| 组件 | 要求版本 | 适用范围 |
|---|---|---|
| JDK / JBR | **21**（Compose Desktop 必须使用 [JBR 21](https://github.com/JetBrains/JetBrainsRuntime/releases)） | 所有 Gradle 操作 |
| Kotlin | 最低 **2.3.0-RC2** | Wasm GC、函数引用、异常处理提案 |
| Android Studio | **LTS** | AGP 9.3.0 兼容性 |
| Zig | **0.16.0** | `wasmline-core` JNI 共享库编译 |
| Python | **3.10+** | `./scripts/wasmline` 仓库命令 |
| Bash | **3.2+** | 内部 JNI 与 Kotlin/Native 构建实现 |

Kotlin/WasmWasi 编译器后端必须支持以下 WebAssembly 提案：

| 提案 | 要求 | 原因 |
|---|---|---|
| GC（垃圾回收） | 必需 | Kotlin 对象在 Wasm 中分配 |
| Function References | 必需 | 接口分发与闭包 |
| Exception Handling | 必需 | Kotlin 异常在 Wasm 中传播 |
| Tail Call Optimization | 推荐 | 减少深层递归的栈使用 |

## 环境变量

构建项目前需配置以下环境变量：

```bash
# Android SDK 路径
export ANDROID_HOME="/home/<user>/Android/Sdk"

# Android NDK 路径
export ANDROID_NDK_HOME="$ANDROID_HOME/ndk/30.0.15729638"

# Windows 交叉编译使用的 MinGW-w64 路径
export MINGW_PATH="/usr/x86_64-w64-mingw32"

# macOS/Homebrew：使用 formula 根目录，build.zig 会自动解析 toolchain-x86_64。
# export MINGW_PATH="$(brew --prefix mingw-w64)"
```

| 变量 | 用途 |
|---|---|
| `ANDROID_HOME` | Gradle 构建 Android 目标时定位 SDK |
| `ANDROID_NDK_HOME` | `./scripts/wasmline jni build` 构建 Android ABI 时定位 NDK 工具链 |
| `MINGW_PATH` | `build.zig` 交叉编译 `x86_64-windows-gnu` 时定位 MinGW 工具链根目录 |

<Callout type="info" title="MINGW_PATH 仅 Windows 交叉编译需要">
  如果不需要构建 Windows 产物，可不设置 `MINGW_PATH`。交叉编译工具链不可用时，不要下载或选择 Windows 目标。
</Callout>

## 检查环境

每个会话仅执行一次仓库预检，执行时机是修改 Wasmline 文件后首次进行必要验证之前。只读任务、Wasmline 之外的修改以及无需验证的文件修改均不执行预检：

```bash
./scripts/wasmline doctor
```

该命令检查 JBR 21、Zig 0.16.0、Wasmtime 文件、JNI 库以及 Kotlin/Native 库。

<Callout type="info" title="local.properties">
  手动执行项目构建或运行相关命令时，项目根目录下需要 `local.properties` 文件。在 Android Studio 中打开项目后会自动创建该文件。请确认此文件存在后再在 IDE 外执行 Gradle 命令。
</Callout>

## 下载原生运行时资产

该步骤只对 Android、iOS 和 Desktop 构建必需。仅面向 Web 的构建不需要
Wasmtime min C API 资产。

在开始原生目标编译前，`build/platforms/` 下必须存在 wasmtime min C-API 头文件与预编译库。先查看目标编号，再下载构建所需的平台文件和引擎文件：

```bash
./scripts/wasmline wasmtime targets
./scripts/wasmline wasmtime download --target linux-x64 --engine pulley
./scripts/wasmline wasmtime download
```

该命令读取 `versions.json` 中固定的版本，并请求对应 release。下载默认全部并发；使用 `--jobs` 限制并发数，需要 HTTP 代理时使用 `--proxy 127.0.0.1:7890`。

## 构建原生库

`./scripts/wasmline jni build` 使用 CMake 和 NDK 构建 Android 库，使用 Zig 构建
JVM Desktop 库，并将结果复制到所选 engine 模块。

Kotlin/Native 使用单独的静态 bridge。engine 模块的 Gradle 任务会为每个可用
Native target 构建 `libwasmtime.a`，并将其写入 engine KLIB。直接构建一个目标：
`./scripts/wasmline kotlin-native build --target linuxX64 --engine pulley`。
支持 `linuxArm64`、`linuxX64`、`mingwX64`、`macosArm64`、`macosX64`、`iosArm64`
和 `iosSimulatorArm64`。Native 使用方不加载 JNI 库。

Apple 目标仅在 Gradle 运行于 macOS 时注册，因为对应 cinterop 任务依赖
Xcode SDK。Linux 与 Windows 开发环境会省略 iOS/macOS 的编译、元数据和发布
任务，因此这些主机上的 `publishToMavenLocal` 只发布当前可用目标。需要 Apple
KLIB 时，应在 macOS 上执行发布。

```bash
# 构建两个引擎。
./scripts/wasmline jni build --engine all

# 构建一个引擎。
./scripts/wasmline jni build --engine pulley
./scripts/wasmline jni build --engine cranelift

# 构建当前主机支持的全部 Kotlin/Native 目标和 engine 库。
./scripts/wasmline kotlin-native build
```

前置条件：
- 已下载构建所需的 Wasmtime 平台文件和引擎文件
- 已设置 `ANDROID_NDK_HOME`（Android 目标）
- 已安装 Zig 0.16.0（JVM Desktop 目标）
- 已设置 `MINGW_PATH`（Windows 交叉编译，可选）

## Gradle 命令

所有操作都在 `wasmline-multiplatform/` 下执行：

```bash
cd wasmline-multiplatform

# 完整项目构建
./gradlew build

# wasmline-loader 模块测试（清单解析、签名校验）
./gradlew :wasmline-loader:jvmTest

# wasmline-cli 模块测试
./gradlew :wasmline-cli:test

# IR 编译器插件 — 从 testData 夹具重新生成测试运行器
./gradlew :wasmline-kotlin-plugin:generateTests

# IR 编译器插件 — box 测试
./gradlew :wasmline-kotlin-plugin:test \
  --tests 'crow.wasmline.kotlin.runners.JvmBoxTestGenerated'

# 将全部模块安装到本地 Maven 仓库（mavenLocal）
./gradlew publishToMavenLocal
```

当前生成器只注册 `JvmBoxTestGenerated`。诊断测试已禁用，仓库中没有
`testData/diagnostics/` 套件或 `JvmDiagnosticsTestGenerated` runner。

Kotlin 示例使用独立的 Gradle build：

```bash
cd ../wasmline-samples/kotlin
./gradlew :sample-plugin:wasmlineAssembleDebug
```

## 同步版本

文档和重复配置中的版本号由 `versions.json` 管理，并通过脚本同步：

```bash
./scripts/wasmline versions sync
./scripts/wasmline versions sync --set wasmtime_version=<new-version>
./scripts/wasmline versions check
```

手动修改 `versions.json` 后执行 `versions sync`。`--set` 是另一种入口，会先更新 manifest 再执行同步。
