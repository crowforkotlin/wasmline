# Building from Source

This page is for contributors who build or modify the Wasmline repository. If
you only want to use Wasmline in an application, see
[Installation](/en/docs/installation).

## Required Tools

| Component | Required Version | Scope |
|---|---|---|
| JDK / JBR | **21** ([JBR 21](https://github.com/JetBrains/JetBrainsRuntime/releases) mandatory for Compose Desktop) | All Gradle operations |
| Kotlin | **2.3.0-RC2** minimum | Wasm GC, function references, exception-handling proposals |
| Android Studio | **LTS** | AGP 9.3.0 compatibility |
| Zig | **0.16.0** | `wasmline-core` JNI shared library compilation |
| Python | **3.10+** | `./scripts/wasmline` repository commands |
| Bash | **3.2+** | Internal JNI and Kotlin/Native build backends |

The Kotlin/WasmWasi compiler backend must support these WebAssembly proposals:

| Proposal | Requirement | Rationale |
|---|---|---|
| GC (garbage collection) | Required | Kotlin object allocation in Wasm |
| Function References | Required | Interface dispatch and closures |
| Exception Handling | Required | Kotlin exception propagation in Wasm |
| Tail Call Optimization | Recommended | Reduces stack use in deep recursion |

## Environment Variables

The following environment variables must be configured before building:

```bash
# Android SDK path
export ANDROID_HOME="/home/<user>/Android/Sdk"

# Android NDK path
export ANDROID_NDK_HOME="$ANDROID_HOME/ndk/30.0.15729638"

# MinGW-w64 toolchain path for Windows cross-compilation
export MINGW_PATH="/usr/x86_64-w64-mingw32"

# macOS/Homebrew: use the formula root; build.zig resolves toolchain-x86_64.
# export MINGW_PATH="$(brew --prefix mingw-w64)"
```

| Variable | Purpose |
|---|---|
| `ANDROID_HOME` | Locates the Android SDK for Gradle builds |
| `ANDROID_NDK_HOME` | Locates the NDK toolchain for `./scripts/wasmline jni build` Android ABI builds |
| `MINGW_PATH` | Locates the MinGW toolchain root for `build.zig` Windows cross-compilation |

<Callout type="info" title="MINGW_PATH is only needed for Windows cross-compilation">
  If Windows artifacts are not required, `MINGW_PATH` can be omitted. Do not download or select the Windows target when its cross-compilation toolchain is unavailable.
</Callout>

## Check the Environment

Run the repository preflight once per session, immediately before the first validation required after changing Wasmline files. Skip it for read-only work, changes outside Wasmline, and file changes that require no validation:

```bash
./scripts/wasmline doctor
```

The command checks JBR 21, Zig 0.16.0, Wasmtime files, JNI libraries, and
Kotlin/Native libraries.

<Callout type="info" title="local.properties">
  When building or running project commands manually, a `local.properties` file is required in the project root. Open the project in Android Studio and it will generate the file automatically. Ensure this file exists before invoking any Gradle commands outside the IDE.
</Callout>

## Download Native Runtime Assets

This step is required for Android, iOS, and Desktop builds. Web-only builds do
not require the Wasmtime min C API assets.

wasmtime min C-API headers and pre-built libraries must be present under `build/platforms/` before native target compilation proceeds. List the configured target ids, then download the exact targets and engines required by the build:

```bash
./scripts/wasmline wasmtime targets
./scripts/wasmline wasmtime download --target linux-x64 --engine pulley
./scripts/wasmline wasmtime download
```

The command reads the pinned version from `versions.json` and requests that exact release. Downloads run concurrently; use `--jobs` to limit concurrency and `--proxy 127.0.0.1:7890` when an HTTP proxy is required.

## Build Native Libraries

`./scripts/wasmline jni build` uses CMake and the NDK for Android, uses Zig for
JVM Desktop, and copies the libraries into the selected engine modules.

Kotlin/Native uses a separate static bridge. Engine Gradle tasks build one
`libwasmtime.a` for each available Native target and embed it in the engine
KLIB. Build one target directly with
`./scripts/wasmline kotlin-native build --target linuxX64 --engine pulley`.
Supported targets are `linuxArm64`, `linuxX64`, `mingwX64`, `macosArm64`,
`macosX64`, `iosArm64`, and `iosSimulatorArm64`. Native consumers do not load
JNI libraries.

Apple targets are registered only when Gradle runs on macOS because their
cinterop tasks require the Xcode SDK. Linux and Windows development builds omit
iOS/macOS compilation, metadata, and publication tasks; `publishToMavenLocal`
therefore publishes only the targets available on that host. Run the publication
on macOS when Apple KLIBs are required.

```bash
# Build both engines.
./scripts/wasmline jni build --engine all

# Build one engine.
./scripts/wasmline jni build --engine pulley
./scripts/wasmline jni build --engine cranelift

# Build Kotlin/Native libraries for every target supported by this host.
./scripts/wasmline kotlin-native build
```

Prerequisites:
- The required Wasmtime targets and engines have been downloaded
- `ANDROID_NDK_HOME` is set (Android targets)
- Zig 0.16.0 is installed (JVM Desktop targets)
- `MINGW_PATH` is set (Windows cross-compilation, optional)

## Gradle Commands

All operations are executed from `wasmline-multiplatform/`:

```bash
cd wasmline-multiplatform

# Full project build
./gradlew build

# wasmline-loader module tests (manifest parsing, cryptographic verification)
./gradlew :wasmline-loader:jvmTest

# wasmline-cli module tests
./gradlew :wasmline-cli:test

# IR compiler plugin — regenerate test runners from testData fixtures
./gradlew :wasmline-kotlin-plugin:generateTests

# IR compiler plugin — box test execution
./gradlew :wasmline-kotlin-plugin:test \
  --tests 'crow.wasmline.kotlin.runners.JvmBoxTestGenerated'

# Install all modules to the local Maven repository (mavenLocal)
./gradlew publishToMavenLocal
```

The generator currently registers only `JvmBoxTestGenerated`. Diagnostic tests
are disabled; there is no `testData/diagnostics/` suite or
`JvmDiagnosticsTestGenerated` runner.

The Kotlin sample is a separate Gradle build:

```bash
cd ../wasmline-samples/kotlin
./gradlew :sample-plugin:wasmlineAssembleDebug
```

## Synchronize Versions

Documentation and duplicated configuration versions are synchronized from
`versions.json`:

```bash
./scripts/wasmline versions sync
./scripts/wasmline versions sync --set wasmtime_version=<new-version>
./scripts/wasmline versions check
```

Run `versions sync` after editing `versions.json`. The `--set` form is an alternative that updates the manifest before synchronizing.
