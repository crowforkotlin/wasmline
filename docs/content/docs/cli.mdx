# CLI Reference

Run the CLI from `wasmline-multiplatform/`. The repository launcher builds the
distribution and forwards every argument to the Kotlin command:

```bash
./wasmline-cli/cli.sh <command> [options]
```

## Command Set

| Command | Purpose |
|---|---|
| `build` | Build the AOT matrix, sign one manifest, and create the complete offline ZIP |
| `compile` | Build the AOT matrix and write `aot-build-record.json` without signing |
| `manifest` | Sign a completed build record without changing its runtime contract |
| `generate-key-pair` | Generate the Ed25519 key pair required by the current manifest format |
| `aot-profiles list` | List catalog profiles with Wasmtime version, backend, and profile ID |
| `aot-profiles describe <id>` | Show the immutable descriptor and build hosts for one profile |
| `componentize` | Create or inspect the raw Component used as AOT input |
| `tools download`, `wit generate`, `component validate`, `component inspect` | Manage Component build tools and metadata |

The removed `download` command, `--wasmtime` directory, and arbitrary compiler
executable options are not accepted. AOT compilers must resolve from the signed
catalog lock.

## Build a Package

```bash
./wasmline-cli/cli.sh generate-key-pair --save

./wasmline-cli/cli.sh build \
  --input plugin.wasm \
  --aot-compatibility current \
  --target pulley64 \
  --target x86_64-linux \
  --auto-download \
  --plugin-id com.example.plugin \
  --version 1.0.0 \
  --build-timestamp 0 \
  --key build/wasmline/keys/ed25519_private.key
```

Native AOT compilation requires one explicit selector. Select the current
generation, the supported minimum, the complete formal catalog, or explicit
inclusive ranges:

```bash
./wasmline-cli/cli.sh compile \
  --input plugin.wasm \
  --aot-compatibility minimum \
  --target pulley64

./wasmline-cli/cli.sh compile \
  --input plugin.wasm \
  --aot-compatibility versionRanges \
  --aot-version-range 1.0.0..1.20.0 \
  --aot-version-range 1.50.0..1.72.3 \
  --target x86_64-linux
```

The ranges are closed and use stable `x.y.z` versions. A selector is resolved
through the local immutable catalog, then converted to exact backend profile IDs.
The CLI does not accept arbitrary Wasmtime versions or profile IDs. Use
`aot-profiles list` and `aot-profiles describe` for diagnostic information only.

## Raw Export ABI

Both `build` and `compile` accept `--raw-abi-metadata <file>` for
`CORE_WASM + RAW_EXPORT`. The bounded JSON file uses the same
`RawAbiMetadata` schema as the Gradle DSL:

```json
{
  "version": 1,
  "exports": [
    {
      "name": "add_i32",
      "kind": "FUNCTION",
      "signature": {
        "parameters": ["I32", "I32"],
        "results": ["I32"]
      }
    }
  ],
  "imports": [],
  "memoryExport": "memory",
  "requiredFeatures": []
}
```

```bash
./wasmline-cli/cli.sh build \
  --input plugin.wasm \
  --execution-model CORE_WASM \
  --invocation-protocol RAW_EXPORT \
  --export-name add_i32 \
  --raw-abi-metadata raw-abi.json \
  --target pulley64 \
  --key build/wasmline/keys/ed25519_private.key
```

The shared plugin-core codec rejects unknown or invalid metadata and
canonicalizes export, import, and feature ordering before the build record is
created. `contractMetadata` remains available for unrelated contract
annotations; it is not a substitute for the raw ABI model.

## Output Layout

```text
build/wasmline/
├── output/com.example.plugin-1.0.0/
│   ├── manifest.wlm
│   ├── artifacts/sha256/
│   │   ├── 4f/4f13c7...a920.cwasm
│   │   ├── 91/91aa42...c810.wasm
│   │   └── b8/b8072d...0f31.pwasm
│   └── debug/
│       ├── manifest.json
│       ├── aot-build-record.json
│       └── artifact-index.json
├── dist/com.example.plugin-1.0.0.zip
└── keys/
    ├── ed25519_private.key
    └── ed25519_public.key
```

One signed `manifest.wlm` describes every requested AOT profile. Core packages
store the Web `.wasm` once, outside the Wasmtime profile matrix. Component
packages use their raw Component only as build input and do not publish it as a
Web artifact. Identical output bytes share one content-addressed file.

The ZIP contains the complete artifact matrix. A remote loader does not fetch
the ZIP: it verifies the manifest, selects one target variant from native runtime
identity, and downloads only that content-addressed artifact.

Compilation and final package publication use staging directories. A failed
matrix unit, signature operation, or ZIP replacement restores both the previous
package directory and the previous offline ZIP.

The Gradle-only `wasmlineCheckAotCompatibility` task performs the optional online
comparison with the latest stable release. CLI compilation remains offline and
uses only its packaged catalog.
