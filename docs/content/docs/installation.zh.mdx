# 安装

Wasmline 以 Maven 构件形式分发，在使用方的 Gradle 项目中直接引入即可。如果你希望从源码构建框架本身或参与贡献，请参阅 [从源码编译](/zh/docs/building-from-source)。

## 环境要求

- JDK / JBR **21**
- Kotlin **2.3.0-RC2** 或更高版本

<Callout type="warn" title="Kotlin 版本要求">
  最低需要 **Kotlin 2.3.0-RC2** 版本。低于该版本时，Kotlin/WasmWasi 编译器后端可能生成不完整的 Wasm 二进制，表现为插件加载失败，或在 `Session.invoke` 边界出现未定义行为。

  ![Kotlin/Wasm 运行时支持矩阵](/images/kotlin_support.png)
</Callout>

## 应用 Gradle 插件

```kotlin
// build.gradle.kts
plugins {
    id("crow.wasmline") version "1.0.0"
}
```

该插件会将 `wasmline-kotlin-plugin` IR 编译器插件应用到当前编译单元，在编译期重写 `link<T>()` 与 `bind(impl)` 调用点。未应用时，这些调用会在运行时抛出 `UnsupportedOperationException`。

## 添加依赖

```kotlin
dependencies {
    implementation(platform("crow.wasmline:wasmline-bom:1.0.0"))

    // 核心加载器：manifest 校验、选择与模块加载
    implementation("crow.wasmline:wasmline-loader")

    // 可选：远程缓存未命中时使用的 HTTP 客户端
    implementation("crow.wasmline:wasmline-network-ktor")

    // 只选择一个 native engine backend
    implementation("crow.wasmline:wasmline-engine-pulley")
}
```

BOM 对 runtime、Loader、network adapter、compiler/Gradle plugin、CLI、
plugin core 和两个 engine 模块施加 strict constraint。所有模块使用同一个
Wasmline `x.y.z` 版本发布，不得单独升级 engine。Native 启动还会在反序列化
任何 AOT artifact 前校验 Wasmline release identity 与 bridge ABI。

| 构件 | 说明 |
|---|---|
| `crow.wasmline:wasmline` | 核心运行时——执行、分发、序列化 SPI |
| `crow.wasmline:wasmline-loader` | Load options、cache/network SPI、`.wlm` 解析与签名校验 |
| `crow.wasmline:wasmline-network-ktor` | 远程加载使用的 Ktor adapter（JVM、Android、Apple、Linux、Windows Native） |
| `crow.wasmline:wasmline-network-okhttp` | 基于 OkHttp 5.x 的 HTTP 网络客户端（JVM/Android） |
| `crow.wasmline:wasmline-engine-pulley` | 仅 Pulley 解释器——仅支持 `.pwasm`，覆盖所有原生目标 |
| `crow.wasmline:wasmline-engine-cranelift` | Cranelift + Pulley 运行时——优先 `.cwasm`，回退 `.pwasm` |

<Callout type="info" title="Network adapter 是可选依赖">
  `wasmline-loader` 定义 network、cache 与 trust 抽象，但不指定 HTTP engine。本地产物与本地 manifest 不需要 network 模块。只有远程 manifest 缺失或过期，或所选 artifact 未命中缓存时，应用才需要选择 Ktor 或 OkHttp；fresh manifest 与对应 artifact 均已缓存时，不提供 network client 也能加载。浏览器 raw `.wasm` 使用 `WasmlineWeb.prefetch()`，不经过这两个 adapter。
</Callout>

## Kotlin/Native 宿主

Kotlin/Native 应用使用与 JVM、Android 宿主相同的 `WasmlineLoader` API。在 Native 源集添加一个引擎依赖后，已发布的 KMP 元数据会为 iOS、macOS、Linux 或 Windows 选择匹配的静态 Wasmtime bridge。

```kotlin
// build.gradle.kts
val wasmlineVersion = "1.0.0"

kotlin {
    sourceSets {
        val nativeMain by getting {
            dependencies {
                implementation("crow.wasmline:wasmline:$wasmlineVersion")
                implementation("crow.wasmline:wasmline-loader:$wasmlineVersion")
                implementation("crow.wasmline:wasmline-engine-pulley:$wasmlineVersion")
                // 需要 .cwasm 时改用 wasmline-engine-cranelift。
            }
        }
    }
}
```

Pulley 在所有 Native 目标上接受 pointer width 匹配的 `.pwasm`。Cranelift
会先按精确 profile、平台、pointer width 与 CPU feature 选择 `.cwasm`。
只有不存在兼容 CWASM，并且 runtime 报告对应 Pulley profile 与 capability 时，
才能使用 `.pwasm`。iOS 仍只使用 `pulley64`。Native 应用不加载 JNI 库，也不
依赖源码目录路径。远程加载可使用 `wasmline-network-ktor`，它会根据 Native
目标选择 Darwin、Curl 或 WinHTTP。

当前 manifest 格式只接受 Ed25519。一个 package 使用一个签名 manifest 描述
全部 AOT compatibility profile 与内容寻址 target。
