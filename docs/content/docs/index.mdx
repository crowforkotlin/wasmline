# WasmLine

Wasmline 是一个 **Kotlin Multiplatform WebAssembly 插件框架**，在统一的 API 表面下，为 Android、iOS、Desktop 和 Web 目标提供加载与分发符合 WASI 规范插件的统一、类型安全执行接口。

项目建立在三个核心不变量之上：

- **编译期桥接生成**：由 Kotlin IR 编译器插件完成
- **双路径执行**：原生目标使用 Wasmtime，Web 使用浏览器原生 `WebAssembly`
- **语言无关的插件编写**：任何可以产出 WASI 二进制的工具链都可以接入

## 平台支持

| 平台 | 宿主 / 目标 | 运行时引擎 | 桥接方式 | 产物支持 | 状态 | 模块加载器 |
|---|---|---|---|---|---|---|
| Android | `arm64-v8a` | Wasmtime v45.0.0 C-API | JNI（Zig 0.15.1 编译） | `.cwasm` / `.pwasm` | 已支持 | `wasmline-core` Session |
| iOS | `arm64` | Wasmtime v45.0.0 C-API | C Interop（`.def` cinterop） | `.pwasm` | 已支持 | `wasmline-core` Session |
| macOS | `arm64` | Wasmtime v45.0.0 C-API | JNI（Zig 0.15.1 编译） | `.cwasm` / `.pwasm` | 已支持 | `wasmline-core` Session |
| Linux | `x86_64` | Wasmtime v45.0.0 C-API | JNI（Zig 0.15.1 编译） | `.cwasm` / `.pwasm` | 已支持 | `wasmline-core` Session |
| Windows | `x86_64` | Wasmtime v45.0.0 C-API | JNI（Zig 0.15.1 编译） | `.cwasm` / `.pwasm` | 已支持 | `wasmline-core` Session |
| Web — Kotlin/JS | 浏览器 JS 引擎 | 浏览器 WebAssembly API | Inline JS | 仅原始 `.wasm` | 已支持 | XHR fetch |
| Web — Kotlin/WasmJS | 浏览器 JS 引擎 | 浏览器 WebAssembly API | Inline JS | 仅原始 `.wasm` | 已支持 | XHR fetch |

<Callout type="info" title="Web 运行时路径">
  Web 目标不会嵌入 Wasmtime。浏览器路径直接通过 `WebAssembly.Module` 与 `WebAssembly.Instance` 实例化插件，并由轻量级内联 JS 运行时提供 Wasmline bridge 协议与最小化 WASI shim。
</Callout>

<Callout type="warn" title="Web 产物限制">
  CLI 流水线生成的 AOT 产物（`.cwasm`、`.pwasm`）不能用于 Web。Web 目标只接受原始 `.wasm` 二进制。
</Callout>

## 集成参考

### 服务契约定义

服务契约是在共享源码（`commonMain`）中声明、并扩展 `WasmlineService` 的 Kotlin `interface`。方法签名构成了 SHA-256 动作标识符派生所依赖的稳定边界。

```kotlin
// shared/src/commonMain/kotlin/com/example/EchoService.kt
import crow.wasmline.WasmlineService

interface EchoService : WasmlineService {
    fun echo(message: String): String
}
```

### 宿主端模块加载与服务调用

```kotlin
import crow.wasmline.WasmlineLoadState
import crow.wasmline.link
import crow.wasmline.bind
import crow.wasmline.loader.loadWasmline

Wasmline.init()

val state = loadWasmline(artifactPath = "/data/plugin.pwasm")

when (state) {
    is WasmlineLoadState.Failure -> error("Plugin load failed: ${state.cause}")
    is WasmlineLoadState.Success -> {
        val module = state.wasmline

        module.bind(object : HostNotificationService {
            override fun notify(event: String) { /* host-side handler */
            }
        })

        val result = module.link<EchoService>().echo("ping")

        module.close()
    }
}
```

<Callout type="info" title="IR 插件重写目标">
  `link<T>()` 与 `bind(impl)` 会由 `wasmline-kotlin-plugin` 重写。若未应用该编译器插件，这两个便捷 API 会在运行时抛出 `UnsupportedOperationException`。
</Callout>

## CLI 参考

所有 CLI 命令都从 `wasmline-multiplatform/` 通过 Gradle 分发：

```bash
cd wasmline-multiplatform
./gradlew :wasmline-cli:run --args="<command> [options]"
```

### 命令集

| 命令 | 说明 |
|---|---|
| `download` | 下载一个或多个目标平台的 Wasmtime 发行版二进制 |
| `generate-key-pair` | 生成 Ed25519 签名密钥对 |
| `compile` | 将原始 `.wasm` 编译为平台特定 `.cwasm` 与可移植 `.pwasm` 产物 |
| `manifest` | 从编译产物集合生成已签名的 `.wlm` 清单 |
| `build` | 执行完整流水线：`compile → manifest → zip packaging` |

### 流水线执行

```bash
cd wasmline-multiplatform

# Download Wasmtime min toolchain binaries
./gradlew :wasmline-cli:run --args="download -v v45.0.0"

# Generate Ed25519 signing key pair
./gradlew :wasmline-cli:run --args="generate-key-pair --save"

# Execute the full build pipeline
./gradlew :wasmline-cli:run --args="build \
  -i plugin.wasm \
  -wt build/wasmline/wasmtime/wasmtime-v45.0.0-aarch64-macos \
  --key build/wasmline/keys/ed25519_private.key"
```

### 构建产物目录结构

```text
build/wasmline/
├── output/{name}-{version}/
│   ├── manifest.wlm                      # Signed manifest (Protobuf + Ed25519 signature)
│   ├── {name}-pulley64.pwasm             # Pulley portable bytecode — all native Wasmtime targets
│   ├── {name}-aarch64-android.cwasm      # AOT — Android arm64-v8a
│   ├── {name}-aarch64-macos.cwasm        # AOT — macOS Apple Silicon
│   ├── {name}-aarch64-ios.cwasm          # AOT — iOS arm64
│   ├── {name}-x86_64-linux.cwasm         # AOT — Linux x86_64
│   ├── {name}-x86_64-windows.cwasm       # AOT — Windows x86_64
│   └── debug/
│       ├── compile-result.json
│       └── manifest.json
├── dist/
│   └── {name}-{version}.zip
└── keys/
    ├── ed25519_private.key
    └── ed25519_public.key
```

### 双路径执行模型

- **原生目标**（`jniMain` / `iosMain`）会经过 `wasmline-core`，再进入 Wasmtime C-API  v45.0.0，并执行预编译的 `.cwasm` 或 `.pwasm` 产物。
- **Web 目标**（`webMain` / `jsMain` / `wasmJsMain`）会经过 `BrowserWasmlineRuntime`、内联 JS `js()` interop 与浏览器原生 `WebAssembly` API，并且只接受原始 `.wasm` 文件。

### 模块依赖关系图

```text
wasmline-cli  ──────►  wasmline-loader  ──────►  wasmline  (core runtime)
                                                       ▲
                               wasmline-core  (C/C++) ─┘  (JNI / C Interop)

wasmline-kotlin-plugin   (compile-time only; no runtime artifact)
wasmline-gradle-plugin  ──►  wasmline-kotlin-plugin
```

## Kotlin/Wasm 兼容性

![Kotlin/Wasm runtime support matrix](/images/kotlin_support.png)

| 提案 | 要求 | 原因 |
|---|---|---|
| GC（垃圾回收） | 必需 | Kotlin 托管对象在 Wasm 线性内存中的分配 |
| Function References | 必需 | 接口 vtable 分发与闭包表示 |
| Exception Handling | 必需 | Kotlin 异常跨 Wasm 边界传播 |
| Tail Call Optimization | 推荐 | 限制深层递归链的栈增长 |

<Callout type="warn" title="编译器基线">
  Wasmline 需要 **Kotlin 2.3.20-RC** 或更高版本。将 `kotlin` 版本降到该基线以下，可能会生成不完整的 Wasm 二进制，并在 `Session.invoke` 边界触发未定义行为。
</Callout>

## 常见问题

<details>
<summary><strong>浏览器执行路径如何在没有 Wasmtime 的情况下实例化插件？</strong></summary>

Web 实现会直接通过浏览器运行时调用 `WebAssembly.Module` 与 `WebAssembly.Instance`。通过 Kotlin `js()` interop 内嵌的自包含 JS 层提供 `wasi_snapshot_preview1` shim 以及 Wasmline `env` bridge 函数。payload 以 Base64 编码字符串跨越 Kotlin–JS 内存边界，AOT 产物不会被接受。

</details>

<details>
<summary><strong><code>.cwasm</code> 与 <code>.pwasm</code> 有什么区别——为什么不用原始 <code>.wasm</code>？</strong></summary>

| 产物 | 编译时机 | 执行方式 | 版本关联性 |
|---|---|---|---|
| `.wasm` | 在加载时（JIT）由宿主 Wasmtime 编译 | Cranelift → 原生代码或 Pulley，取决于配置 | **无 — 与所有 Wasmtime 版本兼容** |
| `.cwasm` | 由 `wasmtime compile` 通过 Cranelift 提前编译 | 直接在原生硬件上执行 | 与编译它的 Wasmtime 版本关联 |
| `.pwasm` | 由 `wasmtime compile` 通过 Cranelift 提前编译 | Wasmtime **Pulley** 解释器 | 与编译它的 Wasmtime 版本关联 |

`.cwasm` 是针对具体 target triple 的原生机器码。`.pwasm` 同样由 Cranelift 预编译，但目标是平台无关的 Pulley ISA，因此一个产物可以跨全部原生 Wasmtime 宿主运行。

由于 `.cwasm` 与 `.pwasm` 都由特定 Wasmtime 版本生成，升级 Wasmtime 后必须重新编译。Web 运行时则是唯一继续使用原始 `.wasm` 的路径。

</details>
