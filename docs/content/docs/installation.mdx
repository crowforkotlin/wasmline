# Installation

Use Wasmline as Maven artifacts in a Gradle project. To build the Wasmline
repository itself, see [Building from Source](/en/docs/building-from-source).

## Requirements

- JBR **21**
- Kotlin **2.3.0-RC2** or later

<Callout type="warn" title="Kotlin requirement">
  The minimum required Kotlin version is **2.3.0-RC2**. Earlier versions can produce incomplete Kotlin/WasmWasi
  binaries. Do not use them for Wasmline plugins.
</Callout>

## Apply the Gradle Plugin

Apply the plugin to each compilation that uses generated `link<T>()` or
`bind(impl)` calls:

```kotlin
// build.gradle.kts
plugins {
    id("crow.wasmline") version "1.0.0"
}
```

The plugin applies `wasmline-kotlin-plugin`. Without it, the public
`Wasmline.callResult(action, bytes)` API remains available, but `link<T>()` and
`bind(impl)` throw `UnsupportedOperationException` at runtime.

## Add Runtime Dependencies

Use the BOM so all Wasmline modules use one version. Add `wasmline-loader` and
exactly one native engine module. Add a network module only when a host must
download a remote manifest or an artifact that is not cached.

```kotlin
dependencies {
    implementation(platform("crow.wasmline:wasmline-bom:1.0.0"))
    implementation("crow.wasmline:wasmline-loader")
    implementation("crow.wasmline:wasmline-engine-pulley")

    // Required only for remote loading on supported native targets.
    implementation("crow.wasmline:wasmline-network-ktor")
}
```

| Module | Use it for |
|---|---|
| `wasmline` | Runtime APIs, service dispatch, and serialization SPI |
| `wasmline-loader` | Manifest parsing, signature checks, cache access, and artifact selection |
| `wasmline-network-ktor` | Remote loading on JVM, Android, Apple, Linux, and Windows Native |
| `wasmline-network-okhttp` | Remote loading on JVM and Android with OkHttp |
| `wasmline-engine-pulley` | Loading matching `.pwasm` artifacts |
| `wasmline-engine-cranelift` | Loading matching `.cwasm`; it can also load matching `.pwasm` |

The BOM keeps the runtime, loader, plugins, CLI, plugin build tools, and engine
modules on the same Wasmline version. Do not upgrade an engine module by itself.

## Kotlin/Native Hosts

Add the same runtime modules to the Native source set. Published Kotlin
Multiplatform metadata selects the matching static Wasmtime bridge for iOS,
macOS, Linux, or Windows.

```kotlin
val wasmlineVersion = "1.0.0"

kotlin {
    sourceSets {
        val nativeMain by getting {
            dependencies {
                implementation("crow.wasmline:wasmline:$wasmlineVersion")
                implementation("crow.wasmline:wasmline-loader:$wasmlineVersion")
                implementation("crow.wasmline:wasmline-engine-pulley:$wasmlineVersion")
            }
        }
    }
}
```

`wasmline-engine-pulley` loads a matching `pulley32` or `pulley64` `.pwasm`.
`wasmline-engine-cranelift` first looks for an exact `.cwasm` target and profile
match. It uses `.pwasm` only when a matching Pulley profile is also available.
iOS uses `pulley64` `.pwasm` only.

<Callout type="info" title="Network modules are optional">
  Local manifests and local artifacts do not need Ktor or OkHttp. The loader
  checks its cache before using a network client. Browser raw `.wasm` loading
  uses `WasmlineWeb.prefetch()` instead of either native network module.
</Callout>

## Current Distribution

Wasmline is currently distributed through `mavenLocal()`. From this repository,
run the following command before consuming the artifacts from another local
project:

```bash
cd wasmline-multiplatform
./gradlew publishToMavenLocal
```
