# Installation

Wasmline is consumed as Maven artifacts in your own Gradle project. If you want to build the framework itself from source or contribute to it, see [Building from Source](/en/docs/building-from-source).

## Requirements

- JDK / JBR **21**
- Kotlin **2.3.0-RC2** or later

<Callout type="warn" title="Kotlin version requirement">
  The minimum required Kotlin version is **2.3.0-RC2**. Below this version, the Kotlin/WasmWasi compiler backend may produce incomplete Wasm binaries, manifesting as plugin load failures or undefined behavior at the `Session.invoke` boundary.

  ![Kotlin/Wasm runtime support matrix](/images/kotlin_support.png)
</Callout>

## Apply the Gradle Plugin

```kotlin
// build.gradle.kts
plugins {
    id("crow.wasmline") version "1.0.0"
}
```

The plugin applies the `wasmline-kotlin-plugin` IR compiler plugin to the current compilation unit, rewriting `link<T>()` and `bind(impl)` call sites at compile time. Without it, those calls throw `UnsupportedOperationException` at runtime.

## Add Dependencies

```kotlin
dependencies {
    implementation(platform("crow.wasmline:wasmline-bom:1.0.0"))

    // Core loader: manifest verification, selection, and module loading
    implementation("crow.wasmline:wasmline-loader")

    // Optional HTTP client for remote cache misses
    implementation("crow.wasmline:wasmline-network-ktor")

    // Select exactly one native engine backend
    implementation("crow.wasmline:wasmline-engine-pulley")
}
```

The BOM applies strict constraints to the runtime, loader, network adapters,
compiler and Gradle plugins, CLI, plugin core, and both engine modules. All of
these artifacts are published with one Wasmline `x.y.z` version. Do not upgrade
an engine independently. Native startup also checks the Wasmline release
identity and bridge ABI before any AOT artifact is deserialized.

| Artifact | Description |
|---|---|
| `crow.wasmline:wasmline` | Core runtime — execution, dispatch, serialization SPI |
| `crow.wasmline:wasmline-loader` | Load options, cache/network SPI, `.wlm` parsing and signature verification |
| `crow.wasmline:wasmline-network-ktor` | Ktor adapter for remote loading (JVM, Android, Apple, Linux, Windows Native) |
| `crow.wasmline:wasmline-network-okhttp` | HTTP network client backed by OkHttp 5.x (JVM/Android) |
| `crow.wasmline:wasmline-engine-pulley` | Pulley-only interpreter — `.pwasm` only, all native targets |
| `crow.wasmline:wasmline-engine-cranelift` | Cranelift + Pulley runtime — `.cwasm` first, `.pwasm` fallback |

<Callout type="info" title="Network adapters are optional">
  `wasmline-loader` defines the network, cache, and trust abstractions but does not select an HTTP engine. Local artifacts and local manifests need no network module. For a remote manifest, choose Ktor or OkHttp only when the application must fetch a missing or expired manifest or a missing artifact. A fresh manifest and its selected artifact can be loaded from cache without a network client. Browser raw `.wasm` loading uses `WasmlineWeb.prefetch()` instead of either adapter.
</Callout>

## Kotlin/Native Host

Kotlin/Native applications use the same `WasmlineLoader` API as JVM and Android hosts. Add one engine dependency to the Native source set; the published KMP metadata selects the matching static Wasmtime bridge for iOS, macOS, Linux, or Windows.

```kotlin
// build.gradle.kts
val wasmlineVersion = "1.0.0"

kotlin {
    sourceSets {
        val nativeMain by getting {
            dependencies {
                implementation("crow.wasmline:wasmline:$wasmlineVersion")
                implementation("crow.wasmline:wasmline-loader:$wasmlineVersion")
                implementation("crow.wasmline:wasmline-engine-pulley:$wasmlineVersion")
                // Use wasmline-engine-cranelift when .cwasm is required.
            }
        }
    }
}
```

Pulley accepts portable `.pwasm` artifacts with the matching pointer width on
every Native target. Cranelift first selects an exact profile, platform, pointer
width, and CPU-feature match for `.cwasm`. It can use `.pwasm` only when no
compatible CWASM exists and the runtime reports the corresponding Pulley profile
and capability. iOS remains `pulley64` only. Native applications do not load JNI
libraries or call a source-checkout path. Remote loading can use
`wasmline-network-ktor`, which selects Darwin, Curl, or WinHTTP for the target.

The current manifest format accepts Ed25519 only. A package contains one signed
manifest for all AOT compatibility profiles and content-addressed targets.

<Callout type="info" title="Distribution status">
  Wasmline is under active development and is not released yet. Artifacts are currently distributed through `mavenLocal()` — run `./gradlew publishToMavenLocal` in `wasmline-multiplatform/` to install them locally. Maven Central publishing is in progress.
</Callout>
