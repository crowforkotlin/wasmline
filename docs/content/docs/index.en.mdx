# WasmLine

Wasmline is a **Kotlin Multiplatform WebAssembly plugin framework** with an API for loading and dispatching WASI-compliant plugins across Android, iOS, Desktop, and Web.

Core design decisions:

- **Compile-time bridge synthesis** through the Kotlin IR compiler plugin
- **Dual-path execution**: Wasmtime on native targets, browser-native `WebAssembly` on Web
- **Language-agnostic plugins** for any toolchain that can emit WASI binaries

## Platform Support

| Platform | Host / Target | Runtime Engine | Bridge | Artifact Support | Status | Module Loader |
|---|---|---|---|---|---|---|
| Android | `arm64-v8a` | Wasmtime v45.0.5 C-API | JNI (Zig 0.15.1 compiled) | `.cwasm` / `.pwasm` | Supported | `wasmline-core` Session |
| iOS | `arm64` | Wasmtime v45.0.5 C-API | C Interop (`.def` cinterop) | `.pwasm` | Supported | `wasmline-core` Session |
| macOS | `arm64` | Wasmtime v45.0.5 C-API | JNI (Zig 0.15.1 compiled) | `.cwasm` / `.pwasm` | Supported | `wasmline-core` Session |
| Linux | `x86_64` | Wasmtime v45.0.5 C-API | JNI (Zig 0.15.1 compiled) | `.cwasm` / `.pwasm` | Supported | `wasmline-core` Session |
| Windows | `x86_64` | Wasmtime v45.0.5 C-API | JNI (Zig 0.15.1 compiled) | `.cwasm` / `.pwasm` | Supported | `wasmline-core` Session |
| Web — Kotlin/JS | Browser JS engine | Browser WebAssembly API | Inline JS | Raw `.wasm` only | Supported | XHR fetch |
| Web — Kotlin/WasmJS | Browser JS engine | Browser WebAssembly API | Inline JS | Raw `.wasm` only | Supported | XHR fetch |

<Callout type="info" title="Web runtime path">
  Web targets do not embed Wasmtime. The browser path instantiates plugins directly with `WebAssembly.Module` and `WebAssembly.Instance`, while an inline JS runtime provides the Wasmline bridge protocol and a minimal WASI shim.
</Callout>

<Callout type="warn" title="Web artifact constraint">
  AOT artifacts generated by the CLI pipeline (`.cwasm`, `.pwasm`) are not valid Web inputs. Web targets accept raw `.wasm` binaries only.
</Callout>

## Installation & Prerequisites

### System Requirements

| Component | Required Version | Scope |
|---|---|---|
| JDK / JBR | **21** ([JBR 21](https://github.com/JetBrains/JetBrainsRuntime/releases) required for Compose Desktop) | All Gradle operations |
| Kotlin | **2.3.20-RC** minimum | Wasm GC, function references, exception handling |
| Android Studio | **LTS** | AGP 9.2.1 compatibility |

## Integration Reference

### Service Contract Definition

A service contract is a Kotlin `interface` extending `WasmlineService`, declared in shared source (`commonMain`). Method signatures form the stable boundary used for SHA-256 action identifier derivation.

```kotlin
// shared/src/commonMain/kotlin/com/example/EchoService.kt
import crow.wasmline.WasmlineService

interface EchoService : WasmlineService {
    fun echo(message: String): String
}
```

### Host-Side Module Loading and Service Invocation

```kotlin
import crow.wasmline.WasmlineLoadState
import crow.wasmline.link
import crow.wasmline.bind
import crow.wasmline.loader.loadWasmline

Wasmline.bootstrap()

// Optional: eager warmup for the backend you know you will use first
Wasmline.warmup(WasmlineWarmupMode.PULLEY)

val state = loadWasmline(artifactPath = "/data/plugin.pwasm")

when (state) {
    is WasmlineLoadState.Failure -> error("Plugin load failed: ${state.cause}")
    is WasmlineLoadState.Success -> {
        val module = state.wasmline

        module.bind(object : HostNotificationService {
            override fun notify(event: String) { /* host-side handler */
            }
        })

        val result = module.link<EchoService>().echo("ping")

        module.close()
    }
}
```

<Callout type="info" title="IR plugin rewrite targets">
  `link<T>()` and `bind(impl)` are rewritten by `wasmline-kotlin-plugin`. Without the compiler plugin applied, both helpers throw `UnsupportedOperationException` at runtime.
</Callout>

## CLI Reference

All CLI commands are dispatched from `wasmline-multiplatform/`:

```bash
cd wasmline-multiplatform
./gradlew :wasmline-cli:run --args="<command> [options]"
```

### Command Set

| Command | Description |
|---|---|
| `download` | Download Wasmtime release binaries for one or more target platforms |
| `generate-key-pair` | Generate an Ed25519 signing key pair |
| `compile` | Compile raw `.wasm` into platform-specific `.cwasm` artifacts and a portable `.pwasm` image |
| `manifest` | Generate a signed `.wlm` manifest from the compiled artifact set |
| `build` | Execute the full pipeline: `compile → manifest → zip packaging` |

### Pipeline Execution

```bash
cd wasmline-multiplatform

# Download Wasmtime min toolchain binaries
./gradlew :wasmline-cli:run --args="download -v v45.0.0"

# Generate Ed25519 signing key pair
./gradlew :wasmline-cli:run --args="generate-key-pair --save"

# Execute the full build pipeline
./gradlew :wasmline-cli:run --args="build \
  -i plugin.wasm \
  -wt build/wasmline/wasmtime/wasmtime-v45.0.5-aarch64-macos \
  --key build/wasmline/keys/ed25519_private.key"
```

### Build Output Layout

```text
build/wasmline/
├── output/{name}-{version}/
│   ├── manifest.wlm                      # Signed manifest (Protobuf + Ed25519 signature)
│   ├── {name}-pulley64.pwasm             # Pulley portable bytecode — all native Wasmtime targets
│   ├── {name}-aarch64-android.cwasm      # AOT — Android arm64-v8a
│   ├── {name}-aarch64-macos.cwasm        # AOT — macOS Apple Silicon
│   ├── {name}-aarch64-ios.cwasm          # AOT — iOS arm64
│   ├── {name}-x86_64-linux.cwasm         # AOT — Linux x86_64
│   ├── {name}-x86_64-windows.cwasm       # AOT — Windows x86_64
│   └── debug/
│       ├── compile-result.json
│       └── manifest.json
├── dist/
│   └── {name}-{version}.zip
└── keys/
    ├── ed25519_private.key
    └── ed25519_public.key
```

### Dual-Path Execution Model

- **Native targets** (`jniMain` / `iosMain`) route through `wasmline-core`, then Wasmtime C-API  v45.0.5, and execute precompiled `.cwasm` or `.pwasm` artifacts.
- **Web targets** (`webMain` / `jsMain` / `wasmJsMain`) route through `BrowserWasmlineRuntime`, inline JS `js()` interop, and the browser-native `WebAssembly` API using raw `.wasm` files only.

### Module Dependency Graph

```text
wasmline-cli  ──────►  wasmline-loader  ──────►  wasmline  (core runtime)
                                                       ▲
                               wasmline-core  (C/C++) ─┘  (JNI / C Interop)

wasmline-kotlin-plugin   (compile-time only; no runtime artifact)
wasmline-gradle-plugin  ──►  wasmline-kotlin-plugin
```

## Kotlin/Wasm Compatibility

![Kotlin/Wasm runtime support matrix](/images/kotlin_support.png)

| Proposal | Requirement | Rationale |
|---|---|---|
| GC (garbage collection) | Mandatory | Kotlin managed-object allocation in Wasm linear memory |
| Function References | Mandatory | Interface vtable dispatch and closure representation |
| Exception Handling | Mandatory | Kotlin exception propagation across the Wasm boundary |
| Tail Call Optimization | Recommended | Limits stack growth in deep recursive chains |

<Callout type="warn" title="Compiler baseline">
  Wasmline requires **Kotlin 2.3.20-RC** or later. Downgrading the `kotlin` version below that baseline can produce incomplete Wasm binaries and undefined behavior at `Session.invoke`.
</Callout>

## Frequently Asked Questions

<details>
<summary><strong>How does the browser execution path instantiate plugins without Wasmtime?</strong></summary>

The Web implementation invokes `WebAssembly.Module` and `WebAssembly.Instance` directly through the browser runtime. A JS layer embedded via Kotlin `js()` interop provides `wasi_snapshot_preview1` shims plus the Wasmline `env` bridge functions. Payloads cross the Kotlin–JS memory boundary as Base64-encoded strings, and AOT artifacts are rejected.

</details>

<details>
<summary><strong>What distinguishes <code>.cwasm</code> from <code>.pwasm</code> — and why not raw <code>.wasm</code>?</strong></summary>

| Artifact | Compiled | Execution | Version coupling |
|---|---|---|---|
| `.wasm` | At load time (JIT) by the host Wasmtime | Cranelift → native or Pulley, depending on configuration | **None** — portable across all Wasmtime versions |
| `.cwasm` | Ahead-of-time by `wasmtime compile` via Cranelift | Directly on native hardware | Coupled to the Wasmtime version that compiled it |
| `.pwasm` | Ahead-of-time by `wasmtime compile` via Cranelift | Wasmtime **Pulley** interpreter | Coupled to the Wasmtime version that compiled it |

`.cwasm` is native machine code for a concrete target triple. `.pwasm` is also precompiled by Cranelift, but targets the platform-independent Pulley ISA so one artifact can run across all native Wasmtime hosts.

Because both `.cwasm` and `.pwasm` are emitted by a specific Wasmtime release, upgrading Wasmtime invalidates them and requires recompilation. The Web runtime is the only path that stays on raw `.wasm`.

</details>
