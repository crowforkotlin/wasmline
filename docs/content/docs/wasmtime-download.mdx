# Wasmtime AOT Compatibility

Wasmline does not treat a Wasmtime version string as proof that serialized AOT
artifacts are compatible. Native AOT compatibility is organized into immutable
Wasmline release generations. Each generation binds one fork distribution and
one Cranelift/Pulley profile pair.

Each profile binds the complete Wasmtime `x.y.z` version, downstream
distribution and source revision, serialized-artifact identity, compile-profile
schema, engine configuration, and artifact backend. Its canonical descriptor is
hashed to a `sha256:<digest>` profile ID. Cranelift and Pulley always have
different IDs, including when they use the same Wasmtime release.

## Configuration

```kotlin
import crow.wasmline.gradle.WasmtimeTarget

wasmline {
    wasmtime {
        aotCompatibility {
            current()
        }
        targets = listOf(
            WasmtimeTarget.PULLEY_64,
            WasmtimeTarget.X86_64_LINUX,
        )
        autoDownload.set(true)
    }
}
```

The four selectors are mutually exclusive:

```kotlin
wasmline {
    wasmtime {
        aotCompatibility {
            minimum()
            // all()
            // versionRanges {
            //     include(from = "1.0.0", through = "1.20.0")
            //     include(from = "1.50.0", through = "1.72.3")
            // }
            suppressCompatibilityWarning.set(true)
        }
    }
}
```

`current()` selects the current generation, `minimum()` selects generations from
the effective supported minimum, and `all()` selects every formal generation in
the local catalog. `versionRanges {}` accepts inclusive `x.y.z` ranges. A selector
is required for native AOT targets; a missing selector fails before compilation.
The warning suppression property only hides the post-build log message.

The public catalog is maintained at the repository root as
`aot-compatibility.json` and is uploaded with each stable release. Run
`./scripts/wasmline aot sync` to validate it and generate the packaged lock. It
contains release switch points and AOT generations, but not profile digests. The
detailed profile and compiler bindings remain in the packaged lock. Runtime
loading uses the exact backend-specific profile ID reported by the linked engine.

## Catalog and Cache

`versions.json` contains scalar project and toolchain versions only.
Maintainers edit the root `aot-compatibility.json` for AOT range and generation
history. `./scripts/wasmline aot sync` derives the packaged
`META-INF/wasmline/aot/aot-compatibility-lock.json` and the identical packaged
public resource. Build tools validate that lock instead of accepting a local
compiler path.

Compiler assets are selected for the machine running the build, not for the
artifact target. Each archive and extracted executable has a locked SHA-256.
The shared cache is content-addressed:

```text
~/.wasmline/toolchains/wasmtime/compiler-assets/
└── sha256/{prefix}/{archiveDigest}/{buildHost}/
```

One archive may serve both backend profiles and is downloaded only once. Cache
hits do not access the network. With `autoDownload = false`, all required assets
must already be present and valid; the build reports every missing profile in
one failure. Arbitrary compiler executables and directories are not supported.

Use the CLI to inspect available profiles:

```bash
./wasmline-cli/cli.sh aot-profiles list
./wasmline-cli/cli.sh aot-profiles describe sha256:<digest>
```

## Target and Runtime Rules

`pulley32` produces 32-bit PWASM and `pulley64` produces 64-bit PWASM. PWASM is
not raw WebAssembly and is selected by pointer width. iOS uses `pulley64`;
32-bit Android uses `pulley32`.

CWASM is matched by the runtime's exact Cranelift profile ID, operating system,
architecture, pointer width, and CPU feature profile. A Cranelift-capable runtime
may fall back to PWASM only when no compatible CWASM variant exists and the
runtime explicitly reports a matching Pulley profile and PWASM capability. A
CWASM download, size, digest, or deserialize failure does not trigger fallback.

Web does not use a Wasmtime profile. A Core package stores one raw `.wasm`
variant for JavaScript WebAssembly engines, regardless of the number of native
AOT profiles.

## Compatibility Check

`wasmlineCheckAotCompatibility` runs after a successful debug or release
assemble. It reads the local catalog, checks the latest stable release catalog
from GitHub with a five-second deadline, and writes a JSON report under
`build/reports/wasmline/`. A later Wasmline release may introduce a new
generation even when its Wasmline version changes only in a patch component. A
generation gap is reported explicitly; repeated Wasmline releases that retain
the same generation do not create repeated AOT builds. Web raw `.wasm` is outside
this native AOT check.

## Adding a Wasmtime Release

Repository maintainers add a generation only when a Wasmline engine release uses
a changed AOT contract. Update the scalar Wasmtime versions in
`versions.json`, append the range in the root `aot-compatibility.json`,
and run:

```bash
./scripts/wasmline versions sync
./scripts/wasmline aot sync
./scripts/wasmline aot check
```

For a new fork distribution, `aot sync` resolves the exact
`crowforkotlin/wasmtime` release and source revision, verifies `SHA256SUMS`, and
temporarily downloads the five full CLI archives to lock each compiler
executable digest. Use `--proxy` or `--jobs` when required. Existing
distributions remain offline and no historical archive is downloaded. Do not
edit the generated detailed lock. A Wasmline release that keeps both profile IDs
unchanged remains in the existing generation.
