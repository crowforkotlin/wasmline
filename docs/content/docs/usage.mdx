# Usage Guide

The following example walks through the complete integration flow: define a service contract, implement it in a plugin, then load the plugin and invoke its services from the host.

## Define the Service Contract

A service contract is a Kotlin `interface` extending `WasmlineService`, declared in shared source (`commonMain`). The contract defines the binary protocol boundary between host and plugin. Each method uses an action in the form `<fully-qualified-contract>#<method-name>`; overloaded method names are not supported.

```kotlin
// shared/src/commonMain/kotlin/com/example/EchoService.kt
import crow.wasmline.WasmlineService

interface EchoService : WasmlineService {
    fun echo(message: String): String
}
```

## Implement the Plugin (WASI Target)

The plugin binary registers service implementations through `Wasmline.current.bind(impl)`. The IR compiler plugin rewrites this call site to register the implementation into the generated `*_WasmlineBridge` at the IR level:

```kotlin
// plugin/src/wasmWasiMain/kotlin/Main.kt
import crow.wasmline.Wasmline
import crow.wasmline.bind

val wasmline = Wasmline.current

fun main() {
    wasmline.bind(object : EchoService {
        override fun echo(message: String): String {
            return "Response from WASI plugin: $message"
        }
    })
}
```

## Host-Side Module Loading and Service Invocation

The host loads a plugin through the suspending `WasmlineLoader.load()` API. Native targets use verified manifests or precompiled `.pwasm` / `.cwasm` artifacts; raw `.wasm` is accepted only by the browser Core Wasmline path. An `http(s)://` source is resolved as a remote manifest and verified before its artifact is loaded. The host then registers host-side service implementations accessible to the plugin via `bind(impl)`, and obtains typed proxies for plugin-side services via `link<T>()`:

```kotlin
import crow.wasmline.WasmlineConfig
import crow.wasmline.WasmlineLoadResult
import crow.wasmline.bind
import crow.wasmline.link
import crow.wasmline.loader.WasmlineLoader
import crow.wasmline.loader.WasmlineLoadOptions
import crow.wasmline.loader.WasmlineTrustedKeySet
import crow.wasmline.network.ktor.KtorNetworkClient

suspend fun main() {
    val module = when (val result = WasmlineLoader.load(
        source = "https://example.com/plugin/manifest.wlm",
        options = WasmlineLoadOptions(
            runtimeConfig = WasmlineConfig(),
            networkClient = KtorNetworkClient(),
            trustedKeys = WasmlineTrustedKeySet.Builder()
                .addHex(
                    algorithm = "Ed25519",
                    keyId = "release",
                    publicKeyHex = "5a778289bee0c57b05a1c48c8ef312da6ce8e4e4f13fc1a2e8e5aa4cde7ae0db",
                )
                .build(),
        ),
    )) {
        is WasmlineLoadResult.Success -> result.wasmline
        is WasmlineLoadResult.Failure -> error(result.failure.message)
    }

    module.bind(object : HostNotificationService {
        override fun notify(event: String) { /* host-side handler */ }
    })

    val response = module.link<EchoService>().echo("ping")
    module.close()
}
```

Local artifacts and local manifests do not require a network artifact. For remote manifests, add either `wasmline-network-ktor` (JVM, Android, iOS) or `wasmline-network-okhttp` (JVM, Android). The adapter is consulted only on a fresh-manifest or artifact cache miss; a fully cached package can load without a network client. The built-in file cache streams artifact bodies into atomically published content-addressed files and evicts older entries above `WasmlineLoadOptions.maxCacheBytes` (512 MiB by default). Applications can also implement `WasmlineNetworkClient`, provide a custom cache, or provide a custom remote resolver.

One remote manifest can contain variants for several Wasmtime AOT profiles and
platforms. The loader verifies the Ed25519 envelope, compares the manifest with
the native engine's backend-specific profile IDs and target identity, and then
requests one content-addressed artifact. A cold load normally performs one
manifest request and one artifact request. It does not download the complete
offline ZIP or unrelated variants. Core Web packages select the single
profile-independent RAW_WASM variant.

## Runtime Lifecycle and API Ownership

`WasmlineLoader`, `WasmlineRuntime`, and a loaded `Wasmline` have separate responsibilities:

| API | Responsibility |
|---|---|
| `WasmlineLoader` | Resolve sources, verify packages, select a compatible artifact, and load it |
| `WasmlineRuntime` | Manage process-wide platform linking, engine warm-up, runtime information, and shutdown |
| `Wasmline` | Represent one loaded artifact and release that handle with `close()` |

Most applications should call `WasmlineLoader.load()` directly. Native linking and engine creation happen lazily. Startup optimization is optional:

```kotlin
import crow.wasmline.WasmlineEngineKind
import crow.wasmline.WasmlineRuntime

WasmlineRuntime.preload() // Link the platform runtime without creating an engine.
WasmlineRuntime.warmUp(WasmlineEngineKind.PULLEY) // Create the selected engine early.
```

`WasmlineRuntime.nativeInfo()` returns the linked native runtime identity and its `supportedEngines`; it returns `null` in a browser. Browser runtimes do not provide native engine warm-up. Repeating `warmUp()` for the selected engine is safe. Switching engines is allowed only after all loaded artifact handles have been closed; otherwise warm-up or a conflicting artifact load fails without invalidating the live handles.

Use `Wasmline.close()` for normal artifact ownership. Reserve `WasmlineRuntime.shutdown()` for process or application teardown because it releases all engines, artifacts, and sessions and invalidates every live `Wasmline` handle.

The complete request overload is public when a load needs metadata or custom resolver hooks:

```kotlin
import crow.wasmline.WasmlineLoadResult
import crow.wasmline.loader.WasmlineLoadRequest
import crow.wasmline.loader.WasmlineLoadOptions
import crow.wasmline.loader.WasmlineLoader
import crow.wasmline.loader.WasmlineRemotePackageResolver
import crow.wasmline.loader.WasmlineSource
import crow.wasmline.loader.WasmlineSourceResolvers

suspend fun loadWithCustomResolver(
    packageUrl: String,
    loadOptions: WasmlineLoadOptions,
    appPackageResolver: WasmlineRemotePackageResolver,
): WasmlineLoadResult =
    WasmlineLoader.load(
        WasmlineLoadRequest(
            source = WasmlineSource.RemoteManifestUrl(packageUrl),
            options = loadOptions,
            metadata = mapOf("channel" to "beta"),
            resolvers = WasmlineSourceResolvers(remotePackage = appPackageResolver),
        ),
    )
```

<Callout type="info" title="IR plugin rewrite targets">
  `link<T>()` and `bind(impl)` are Kotlin IR compiler plugin rewrite targets. The IR plugin replaces each call site with a direct invocation of the synthesized `*_WasmlineBridge`. If the `wasmline-kotlin-plugin` is not applied to the compilation unit, these functions throw `UnsupportedOperationException` at runtime.
</Callout>

## Select an Invocation Path

Use `WasmlineArtifactDescriptor` when the artifact is not a default Core Wasmline module. The execution model and invocation protocol are validated as a pair:

```kotlin
import crow.wasmline.WasmlineArtifactDescriptor
import crow.wasmline.WasmlineArtifactFormat
import crow.wasmline.WasmlineComponentValue
import crow.wasmline.WasmlineEngineKind
import crow.wasmline.WasmlineExecutionModel
import crow.wasmline.WasmlineInvocationProtocol
import crow.wasmline.WasmlineLoadResult
import crow.wasmline.WasmlineRuntime
import crow.wasmline.invokeComponentResult
import crow.wasmline.invocation.WasmlineCallResult
import crow.wasmline.loader.WasmlineLoader

val runtime = requireNotNull(WasmlineRuntime.nativeInfo())
val pulleyProfileId = requireNotNull(
    runtime.aotCompatibilityProfileIdsByBackend[WasmlineEngineKind.PULLEY],
).single()
val result = WasmlineLoader.load(
    WasmlineArtifactDescriptor(
        path = "component.pwasm",
        artifactFormat = WasmlineArtifactFormat.PWASM,
        architecture = "pulley${runtime.pointerWidth}",
        pointerWidth = runtime.pointerWidth,
        aotCompatibilityProfileId = pulleyProfileId,
        executionModel = WasmlineExecutionModel.COMPONENT_MODEL,
        invocationProtocol = WasmlineInvocationProtocol.COMPONENT_EXPORT,
        exportName = "wasmline:sample-component-export/calculator@1.0.0#add",
        contractMetadata = mapOf("params" to "s32,s32", "result" to "s32"),
    ),
)

when (result) {
    is WasmlineLoadResult.Success -> when (
        val call = result.wasmline.invokeComponentResult(
            exportName = "add",
            arguments = listOf(WasmlineComponentValue.S32(1), WasmlineComponentValue.S32(2)),
        ),
    ) {
        is WasmlineCallResult.Success -> useValues(call.value.values)
        is WasmlineCallResult.Failure -> log(call.failure.message)
    }

        is WasmlineLoadResult.Failure -> log(result.failure.message)
}
```

This explicit descriptor form is intended for a known local artifact. For a
package manifest, pass its path or URL and let the shared selector choose CWASM,
PWASM, or Web WASM. Do not derive an AOT profile from `wasmtimeVersion`.

`WASMLINE_SERVICE` is the service protocol. `CORE_WASM` can use either that
Service bridge or `RAW_EXPORT`. Raw Export uses `CoreWasmModule` and
`CoreWasmSession` with `RawValue` (`i32`, `i64`, `f32`, `f64`), multi-value
results, synchronous `RawImport` callbacks, and checked `RawMemory`; it does
not use action/payload frames. On Web, register bytes with
`WasmlineWeb.registerBytes()` or prefetch them before loading, and register all
imports before `instantiate()`. Web `i64` uses `BigInt` at the JavaScript
boundary, and imports cannot wait for asynchronous APIs. Native Raw Export
loads matching `.cwasm` or `.pwasm` artifacts through Wasmtime. The Component
Model path remains a separate typed WIT boundary. The runtime does not run
WIT-to-Wasm or binding tools during load; the optional Gradle/CLI Component
pipeline performs that build step ahead of time. See the [Wasmline Service
guide](/en/docs/component-service) for the Service envelope and callback flow.

For a direct Core Wasm module, keep loading and instantiation separate so every
host import is registered before the WebAssembly instance is created:

```kotlin
import crow.wasmline.CoreWasmSessionOptions
import crow.wasmline.RawAbiMetadata
import crow.wasmline.RawExport
import crow.wasmline.RawExportKind
import crow.wasmline.WasmlineArtifactDescriptor
import crow.wasmline.WasmlineArtifactFormat
import crow.wasmline.RawFunctionSignature
import crow.wasmline.RawImport
import crow.wasmline.RawImportDeclaration
import crow.wasmline.RawValue
import crow.wasmline.RawValueType
import crow.wasmline.WasmlineCoreLoadResult
import crow.wasmline.WasmlineExecutionModel
import crow.wasmline.WasmlineInvocationProtocol
import crow.wasmline.WasmlineWeb
import crow.wasmline.invocation.WasmlineCallResult
import crow.wasmline.loader.WasmlineLoader

WasmlineWeb.registerBytes("math.wasm", wasmBytes)
val module = when (val loaded = WasmlineLoader.loadCoreModule(
    WasmlineArtifactDescriptor(
        path = "math.wasm",
        artifactFormat = WasmlineArtifactFormat.RAW_WASM,
        executionModel = WasmlineExecutionModel.CORE_WASM,
        invocationProtocol = WasmlineInvocationProtocol.RAW_EXPORT,
        rawAbi = RawAbiMetadata(
            exports = listOf(
                RawExport(
                    name = "add",
                    kind = RawExportKind.FUNCTION,
                    signature = RawFunctionSignature(
                        parameters = listOf(RawValueType.I32, RawValueType.I32),
                        results = listOf(RawValueType.I32),
                    ),
                ),
            ),
            imports = listOf(
                RawImportDeclaration(
                    module = "env",
                    name = "host_add",
                    signature = RawFunctionSignature(
                        parameters = listOf(RawValueType.I32, RawValueType.I32),
                        results = listOf(RawValueType.I32),
                    ),
                ),
            ),
        ),
    ),
)) {
    is WasmlineCoreLoadResult.Success -> loaded.module
    is WasmlineCoreLoadResult.Failure -> error("${loaded.failure.code}: ${loaded.failure.message}")
}

val session = module.instantiate(
    CoreWasmSessionOptions(
        imports = listOf(
            RawImport(
                module = "env",
                name = "host_add",
                signature = RawFunctionSignature(
                    parameters = listOf(RawValueType.I32, RawValueType.I32),
                    results = listOf(RawValueType.I32),
                ),
            ) { _, values ->
                WasmlineCallResult.Success(
                    listOf(RawValue.I32((values[0] as RawValue.I32).value + (values[1] as RawValue.I32).value)),
                )
            },
        ),
    ),
).getOrThrow()

val values = session.invoke("add", listOf(RawValue.I32(2), RawValue.I32(3))).getOrThrow()
session.memory?.write(0, byteArrayOf(1, 2, 3))?.getOrThrow()
session.close()
module.close()
```

The canonical failure types are `WasmlineFailure` for result values,
`WasmlineException` for explicit throwing adapters, and `WasmlineLoadFailure`
for failures that happen before a module exists. Result APIs expose
`failure`, `failure.code`, and `failure.message` as their only failure model.

## Result and Exception Boundary

Use `callResult`, `invokeRawResult`, and the Core session API when normal call
failures should be handled as data. The result has either `Success(value)` or
`Failure(failure)`; inspect `failure.code` rather than parsing the message.

An action that has no bound handler returns `ACTION_NOT_BOUND`. It is not represented by an empty payload and does not crash the host. Unknown actions, invalid payloads, handler failures, traps, transport failures, and malformed response frames also return a failure result when the runtime can construct one.

`getOrNull()` and `failureOrNull()` provide non-throwing reads.
`throwOnFailure()` adapts a `WasmlineFailure` to `WasmlineException` explicitly;
it is not part of the default result path.

The Core response frame uses the fixed `WLMF` magic marker and a one-byte `frameVersion`. The current value is `1`. The magic marker identifies the frame entry format; it is not authentication. `frameVersion` identifies the response byte layout; it is not the Wasmtime, Kotlin, framework, or business API version. Raw Export and Component Model calls do not add this Core frame.

## Stable Error Codes

Error codes are stable identifiers. Applications should branch on the code and use the message only for diagnostics.

| Code | Value | Meaning |
|---|---:|---|
| `ACTION_NOT_BOUND` | `1001` | No handler is bound for the action scope. |
| `UNKNOWN_ACTION` | `1002` | The action name is not registered. |
| `INVALID_PAYLOAD` | `1003` | The payload or typed arguments are invalid. |
| `HANDLER_FAILED` | `1004` | A handler failed during execution. |
| `SERIALIZATION_FAILED` | `1005` | Business data could not be serialized. |
| `ENGINE_NOT_INITIALIZED` | `2001` | The Wasmtime engine is not initialized. |
| `CORE_TRAP` | `2002` | Core Wasm execution trapped. |
| `CORE_EXPORT_NOT_FOUND` | `2003` | A Core export is missing. |
| `INVOCATION_PROTOCOL_MISMATCH` | `2004` | The descriptor and call API do not match. |
| `MODULE_FORMAT_INVALID` | `2201` | The raw or AOT module format is invalid. |
| `WASM_FEATURE_UNSUPPORTED` | `2202` | A required WebAssembly feature is unavailable. |
| `IMPORT_MISSING` | `2203` | A declared host import was not registered. |
| `IMPORT_SIGNATURE_MISMATCH` | `2204` | An import signature does not match the module. |
| `INSTANTIATION_FAILED` | `2205` | Module instantiation failed. |
| `EXPORT_KIND_MISMATCH` | `2206` | An export exists but has the wrong kind. |
| `ARGUMENT_COUNT_MISMATCH` | `2207` | The argument count is incorrect. |
| `ARGUMENT_TYPE_MISMATCH` | `2208` | An argument type is incorrect. |
| `RESULT_TYPE_UNSUPPORTED` | `2209` | A result type is outside the scalar ABI. |
| `MEMORY_OUT_OF_BOUNDS` | `2210` | A linear-memory range is invalid. |
| `IMPORT_HANDLER_FAILED` | `2211` | A synchronous host import failed. |
| `SESSION_CLOSED` | `2212` | A closed module or session was used. |
| `CONCURRENT_ACCESS` | `2213` | A session already has an active operation. |
| `REENTRANT_CALL` | `2214` | An import callback reentered its session. |
| `UNSUPPORTED_EXPORT_KIND` | `2215` | The backend cannot use the requested export kind. |
| `WASM_TRAP` | `2216` | Core Wasm execution trapped. |
| `EXPORT_SIGNATURE_MISSING` | `2217` | A Web call lacks signature metadata. |
| `EXPORT_NOT_FOUND` | `2218` | The requested raw export is missing. |
| `COMPONENT_TRAP` | `2101` | Component Model execution trapped. |
| `COMPONENT_EXPORT_NOT_FOUND` | `2102` | A Component export is missing. |
| `COMPONENT_CALL_FAILED` | `2103` | A Component call did not return successfully. |
| `RESPONSE_MALFORMED` | `3001` | The response frame is invalid. |
| `RESPONSE_MISSING` | `3002` | No response was returned. |
| `TRANSPORT_FAILURE` | `3003` | A platform bridge failed. |
| `RESPONSE_UNSUPPORTED_VERSION` | `3004` | The Core response frame version is unsupported. |
