# Wasmtime AOT 兼容性

Wasmline 不会把 Wasmtime 版本字符串直接作为 serialized AOT artifact 的兼容
证明。Native AOT 兼容性按不可变的 Wasmline 发行 generation 管理。每个
generation 绑定一个 fork distribution 以及一组 Cranelift/Pulley profile。

每个 profile 绑定完整 Wasmtime `x.y.z`、downstream distribution、source
revision、serialized-artifact identity、compile-profile schema、engine
configuration 与 artifact backend。其规范化描述会计算为
`sha256:<digest>` profile ID。即使使用同一 Wasmtime release，Cranelift 与
Pulley 也始终具有不同 ID。

## 配置

```kotlin
import crow.wasmline.gradle.WasmtimeTarget

wasmline {
    wasmtime {
        aotCompatibility {
            current()
        }
        targets = listOf(
            WasmtimeTarget.PULLEY_64,
            WasmtimeTarget.X86_64_LINUX,
        )
        autoDownload.set(true)
    }
}
```

四种 selector 互斥：

```kotlin
wasmline {
    wasmtime {
        aotCompatibility {
            minimum()
            // all()
            // versionRanges {
            //     include(from = "1.0.0", through = "1.20.0")
            //     include(from = "1.50.0", through = "1.72.3")
            // }
            suppressCompatibilityWarning.set(true)
        }
    }
}
```

`current()` 选择当前 generation，`minimum()` 选择从有效支持下限开始的
generation，`all()` 选择本地 catalog 中全部正式 generation，
`versionRanges {}` 接受闭区间 `x.y.z`。Native AOT target 必须配置 selector；
缺少 selector 时会在编译前失败。警告抑制属性只隐藏构建后的日志消息。

公开 catalog 由仓库根目录的 `aot-compatibility.json` 维护，并随每个稳定版本
发布。执行 `./scripts/wasmline aot sync` 会校验该文件并生成 packaged lock。
它只包含发行切换点和 AOT generation，不包含 profile digest。详细 profile 与
compiler binding 保留在 packaged lock 中。运行时加载仍使用已链接 engine
实际报告的 backend-specific profile ID。

## Catalog 与缓存

`versions.json` 只维护项目和工具链的标量版本。维护者在根目录
`aot-compatibility.json` 中维护 AOT 范围和代际历史。执行
`./scripts/wasmline aot sync` 会生成 packaged
`META-INF/wasmline/aot/aot-compatibility-lock.json` 以及逐字节一致的 packaged
公共资源。构建工具校验该 lock，不接受任意本地 compiler 路径。

Compiler asset 根据执行构建的机器选择，而不是根据 artifact target 选择。
每个 archive 和解压后的 executable 都有锁定的 SHA-256。共享缓存按内容寻址：

```text
~/.wasmline/toolchains/wasmtime/compiler-assets/
└── sha256/{prefix}/{archiveDigest}/{buildHost}/
```

同一个 archive 可以同时服务两个 backend profile，并且只下载一次。命中缓存
时不会访问网络。设置 `autoDownload = false` 后，全部所需资产必须已存在并通过
校验；构建会在一次失败中列出全部缺失 profile。不支持任意 compiler executable
或目录。

使用 CLI 检查可用 profile：

```bash
./wasmline-cli/cli.sh aot-profiles list
./wasmline-cli/cli.sh aot-profiles describe sha256:<digest>
```

## Target 与运行时规则

`pulley32` 生成 32 位 PWASM，`pulley64` 生成 64 位 PWASM。PWASM 不是 raw
WebAssembly，Loader 按 pointer width 选择。iOS 使用 `pulley64`，32 位 Android
使用 `pulley32`。

CWASM 按 runtime 实际报告的 Cranelift profile ID、操作系统、架构、pointer
width 与 CPU feature profile 精确匹配。只有不存在兼容 CWASM，且 runtime
明确报告匹配的 Pulley profile 和 PWASM capability 时，Cranelift runtime 才能
回退到 PWASM。CWASM 下载、size、digest 或 deserialize 失败不会触发回退。

Web 不使用 Wasmtime profile。无论 native AOT profile 数量是多少，Core package
都只保存一个供 JavaScript WebAssembly engine 使用的 raw `.wasm` variant。

## 兼容性检查

`wasmlineCheckAotCompatibility` 会在 debug 或 release assemble 成功后执行。
它读取本地 catalog，在五秒总时限内检查 GitHub 最新稳定发行版的 catalog，并
将 JSON 报告写入 `build/reports/wasmline/`。即使 Wasmline 只发生 patch 版本
变化，也可能增加新的 generation；报告会明确显示 generation gap。若连续多个
Wasmline 发行版保持相同 generation，则不会重复 AOT 构建。Web raw `.wasm`
不属于该 native AOT 检查范围。

## 增加 Wasmtime Release

只有 Wasmline engine 发行版实际改变 AOT contract 时，仓库维护者才会增加
generation。更新 `versions.json` 中的 Wasmtime 标量版本，在根目录
`aot-compatibility.json` 追加 range，然后执行：

```bash
./scripts/wasmline versions sync
./scripts/wasmline aot sync
./scripts/wasmline aot check
```

对于新的 fork distribution，`aot sync` 会解析准确的
`crowforkotlin/wasmtime` release 和 source revision，校验 `SHA256SUMS`，并临时
下载五个完整 CLI archive，以锁定每个 compiler executable 的摘要。维护环境
需要时可以使用 `--proxy` 或 `--jobs`。已有 distribution 的同步保持离线，不会
下载历史 archive。不得手工编辑生成的详细 lock。如果发行版保持两个 profile
ID 不变，则继续使用已有 generation。
