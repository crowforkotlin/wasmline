# Wasmline

Wasmline is a **Kotlin Multiplatform plugin framework** built on top of [Wasmtime](https://wasmtime.dev/).
It focuses on loading **WASI plugins**, packaging them for multiple platforms, and building a gradual path from low-level `action + ByteArray` transport to a typed service layer generated by the Kotlin compiler plugin.

## What Wasmline covers

Today the repository contains three main layers:

- **Runtime and native bridge** — load modules, manage sessions, and move bytes between host and plugin
- **Packaging and distribution** — compile, sign, describe, and ship plugin artifacts
- **Compiler and Gradle tooling** — generate typed glue and improve the Kotlin authoring experience

## Current status

### Ready or actively usable

- Wasmtime-based runtime integration across JVM / Android / iOS oriented targets
- low-level host ↔ plugin RPC based on `action: String` and `payload: ByteArray`
- CLI pipeline for download, compile, manifest generation, signing, and packaging
- sample applications and sample plugins
- phase-one Kotlin IR compiler-plugin generation for:
  - `*_WasmlineDefinition`
  - `*_WasmlineProxy`
  - `*_WasmlineAdapter`

### Still in progress

- full typed service round-trip generation on top of the runtime transport
- richer adapter binding logic
- more compiler-plugin diagnostics and IR test coverage

## Architecture snapshot

At a high level, Wasmline is evolving toward this layering:

1. **Transport layer**
   - low-level `invoke(action, payload)`-style communication
   - host → plugin and plugin → host message flow
2. **Runtime layer**
   - endpoints, sessions, module lifecycle, binding scopes, dispatch
3. **Typed service layer**
   - `WasmlineService` contracts
   - generated definition / proxy / adapter glue
4. **Tooling layer**
   - Gradle plugin, compiler plugin, CLI, test fixtures, snapshots

For the longer design discussion, see `structs/wasmline-ir-design.md`.

## Quick start

### Requirements

- JDK 21+
- Zig 0.15.1+ for native/JNI builds
- Wasmtime artifacts initialized locally when needed

### Initialize local prerequisites

```zsh
sh ./scripts/init.sh
```

### Typical Gradle entry point

Run Gradle commands from `wasmline-multiplatform/`:

```zsh
cd wasmline-multiplatform
./gradlew build
```

### Useful commands

```zsh
cd wasmline-multiplatform

./gradlew :wasmline-loader:jvmTest
./gradlew :wasmline-cli:test
./gradlew :wasmline-sample:plugin:compileProductionLibraryKotlinWasmWasiOptimize
./gradlew :wasmline-kotlin-plugin:test --tests 'crow.wasmline.kotlin.runners.JvmBoxTestGenerated'
```

## CLI pipeline at a glance

Wasmline CLI commands are exposed through Gradle:

```zsh
cd wasmline-multiplatform
./gradlew :wasmline-cli:run --args="<command> [options]"
```

Main commands:

- `download` — fetch Wasmtime distributions
- `generate-key-pair` — create signing keys
- `compile` — build AOT plugin artifacts
- `manifest` — generate signed plugin metadata
- `build` — run the full packaging pipeline

See `wasmline-multiplatform/wasmline-cli/` for command-level details.
